🔒 파운데이션 모델은 닫힌 시스템이다

학습 데이터에 갇혀 있다

그래서 많은 경우 모델에게 추가 정보를 따로 넣어 줘야 한다. 그 정보는 —

  • 모델을 학습시키던 시점에는 아직 일어나지 않았던 최근 사건
  • 애초에 비공개·기밀이라 모델 학습자들이 손댈 수 없었던 자료
🎓 비유 — 아주 똑똑하지만 2년 전에 도서관에서 나온 뒤로 바깥 소식을 전혀 못 들은 천재. "우리 회사 이번 분기 매출은?"이라고 물으면 모른다고 하면 다행인데, 실제로는 그럴듯하게 지어냅니다. 천재라서 말이 되게 지어내요.
1장에서 본 "모델을 믿지 말고 다룰 구조를 설계하라"가 여기서 구체적인 방법으로 나타납니다.

💰 다시 학습시키면 되지 않나 — 안 된다

지식을 더하겠다고 LLM을 다시 학습시키거나 계속 사전학습(continuing pretraining, CPT)을 돌리는 것은 현실적이지 않다.

1단 한 번의 학습 실행조차 비용이 상당하다
2정보는 아주 빠르게 바뀌므로 CPT를 아주 자주 돌려야 한다
규모비용 (책의 각주 추정)
2025년 세대 프런티어 모델 학습
Gemini 2.0, GPT-4		수천만 달러
130억 파라미터 모델 + 새 문서 100만 쪽수만 달러
매일 학습해야 한다면연간 약 1,000만 달러
그래서 보통은
파운데이션 모델은 있는 그대로 쓰고

1장의 블룸버그 CPT 사례와 이어집니다. 도메인 특화 학습에 큰돈을 썼는데 몇 달 뒤 범용 모델이 능가해 버린 사건이죠.

📚 RAG의 등장

📜 Lewis 외 (2020) — 페이스북 AI 리서치(현 Meta)

"Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks"

이전닫힌 시스템
학습 데이터에 갇힘
→
RAG 이후열린 시스템
필요할 때 외부 지식을

retrieval-augmented generation, RAG
💡 RAG는 파운데이션 모델을 "똑똑한 조사원"으로 바꿔 놓습니다 — 자기 지식을 보충하려고 외부 출처를 찾아보는 조사원.
2020년 논문인데 지금도 실무의 기본기입니다. 그만큼 발상이 견고했다는 뜻이에요.

📏 RAG = 세 단계로 조립되는 시스템

미리 (배치)인덱싱
indexing
→
질의마다검색
retrieval
→
질의마다생성
generation
단계비유 — 서류함언제
인덱싱서류를 잘라 색인표를 붙여 서류함에 정리미리 (배치)
검색질문을 듣고 관련 서류만 몇 장 뽑아 옴질문 올 때마다
생성그 서류를 같이 건네며 답을 부탁질문 올 때마다
💡 직접 배포해야 하지만 구성 요소는 상당히 자유롭게 갈아 끼울 수 있습니다. 그래서 RAG는 "하나의 기법"이 아니라 시스템으로 보는 게 맞습니다.
인덱싱은 미리 한 번, 검색과 생성은 질의가 올 때마다입니다. 이 구분이 비용 구조를 결정합니다.

⚠️ 이 장만은 순서대로 다 읽어라

이 책의 다른 장과 달리, 3·4장은 자기 문제에 맞는 패턴만 골라 읽지 말라는 것이 저자의 권고다.

패턴들이 서로 위에 쌓인다
점점 까다로워지는 요구사항을 감당할 능력을 더해 간다
📈 그림 3-1에서 상자는 패턴, 화살표는 왜 한 단계 위로 올라가고 싶어지는지를 나타냅니다. 예를 들어 관련 없는 콘텐츠나 모호성을 처리해야 한다면 패턴 9에서 패턴 10으로 올라가게 됩니다.
✅ 그렇다고 여기 나오는 아이디어를 전부 써야 하는 건 아닙니다. 무엇이 필요한지는 ① 시스템의 용도(전문가용 내부 도구인가, 수백만 고객이 쓸 제품인가?) ② 내 RAG가 실제로 마주할 질문과 문서의 유형에 달렸습니다.
저자가 이렇게 못 박는 장은 여기뿐입니다. 그만큼 패턴들이 서로 의존한다는 뜻이에요.

패턴 6 기본 RAG — 요약

❌ 문제

지식 컷오프 · 모델 용량 한계 · 비공개 데이터 접근 부재. 그 결과 환각과 출처를 댈 수 없음

✅ 해법

관련 청크를 프롬프트에 넣어 응답을 그라운딩(근거 대기). 검색은 BM25 같은 키워드 기반

🎯 작동 원리는 프라이밍(priming) — LLM은 프롬프트 안의 정보를 우선적으로 사용합니다. 컨텍스트 한 줄이 학습된 지식을 덮어쓸 수도 있어요.
⚠️ 이걸 그대로 쓰게 되리라 기대하지 말 것. 저자는 이 단순한 구현의 한계가 나머지 패턴이 왜 필요한지를 설명하기 때문에 다룬다고 명시합니다.

패턴 7 의미 기반 색인 — 요약

❌ 문제

같은 뜻 다른 단어. 질의는 "AI"인데 문서는 "Artificial Intelligence". 동의어·다국어·이미지·표·레이아웃을 키워드로는 못 다룬다

✅ 해법

임베딩으로 의미를 색인한다. 청크를 고차원 벡터로 바꿔 벡터 스토어에 저장

🗺️ 비유 — 단어 색인이 아니라 주제 좌표. "심장마비"로 물어도 "급성 심근경색" 문서가 나옵니다. 단어가 하나도 안 겹치는데 좌표가 옆자리이기 때문입니다.
🔢 기억할 숫자 — 임베딩 차원 보통 768~4,096 · Anthropic의 컨텍스추얼 리트리벌은 잘못된 검색 비율을 67% 낮췄다

패턴 8 대규모 색인 운영 — 요약

❌ 문제

중의성 · 데이터 최신성 · 상충하는 정보 · 임베딩 모델 지원 종료. 장난감 문제에서는 안 보이던 것들

✅ 해법

메타데이터로 필터링 · 재순위화 · 정리. 그리고 수명 주기를 통제할 수 있는 임베딩 모델 선택

색인이 커지면 문제는 못 찾는 것이 아니라
서로 다른 답이 다 찾아지는 것
📈 실제 사례 — 고혈압 기준이 140/90 → 130/80(2017 AHA·ACC) → 2022년 AAFP는 다시 140/90이 낫다고 발표. 셋 다 색인에 있으면 같은 질문에 매번 다른 답이 나옵니다.

🧭 RAG를 안 써도 되는 경우

문서가 충분히 작다면 검색 부분이 필요 없을 수도 있다. 문서 전체를 프롬프트에 넣고 답을 생성하게 하면 된다.

전체를 넣으면
청킹이나 검색에서 생기는 오류를 걱정할 필요가 없다
기준내용 (2025년 6월 집필 시점)
20만 토큰약 500쪽. 대부분의 LLM 컨텍스트 윈도우에 무리 없이 들어간다 → RAG 불필요
200만 토큰프런티어 모델의 최대치. 프랑스 세법 전체를 담기에 얼추 충분하다
💰 비용은 Prompt Caching(8장 패턴 25)으로 잡습니다. 멀티모달 LLM이 토큰화와 임베딩을 미리 계산해 두고 질의마다 재사용하므로 합리적인 수준이 됩니다.
⚠️ 다만 구체적인 정보를 찾아야 할 때는 적절한 겹침을 둔 전략적 청킹이 더 나은 검색 성능을 내는 경우가 많습니다.
먼저 이걸 검토하라는 게 저자의 조언입니다. RAG는 복잡도가 큰 시스템이라 안 써도 되면 안 쓰는 게 낫습니다.
