🧩 왜 "조립 가능"인가

📑 패턴 23과 같은 유스케이스, 다른 방식 — 이 장의 워크플로는 7장 패턴 23에서 봤던 교육용 콘텐츠 만들기 그대로입니다. 다만 어떤 멀티에이전트 프레임워크도 쓰지 않고 만듭니다.
가장 성공적인 구현들은
복잡한 프레임워크가 아니라
단순하고 조립 가능한 패턴을 쓴다
— Anthropic, 효과적인 에이전트를 만드는 법
🔧 저자는 이것이 유닉스 철학을 떠올리게 한다고 말합니다 — 작은 도구를 하나씩 잘 만들고 파이프로 잇는 방식이죠.
🎯 목표 — 이 책에서 조립 가능한 패턴 묶음을 살펴봤으니, 이제 그것들로 LLM에도 클라우드에도 매이지 않는 효과적인 멀티에이전트 · 멀티스텝 워크플로를 만든다.
💡 7장 패턴 23의 결론이 여기서 실행됩니다 — 그 절에서 저자들은 "단순하고 조합 가능한 패턴을 쓰라"는 Anthropic의 권고를 인용하고 "단일 에이전트로 되면 그냥 그렇게"라고 했습니다. 10장은 그 말대로 프레임워크를 걷어낸 구현입니다.
말만 하고 끝내지 않고 실제로 그렇게 만들어 보인 것이 이 장의 미덕입니다.

📌 옮긴이 주 두 가지

🖼️ 1. 그림 속 UI 문자열은 영어 그대로

그림 10-2 ~ 10-7은 독자가 직접 실행하게 될 예제 앱의 실제 화면입니다. 화면에 찍힌 Select topic, Assign to Writer, HISTORIAN 같은 글자는 그 앱이 실제로 출력하는 문자열이라 한국어로 바꾸면 독자가 보게 될 화면과 어긋납니다.

→ UI 문자열은 원문 그대로 두고, 저자가 그림 위에 덧붙인 주석만(그림 10-7의 초록 · 파란 글씨) 옮겼습니다. 각 화면의 뜻은 캡션 괄호 안에 붙였습니다.
🔢 2. 패턴 번호는 장을 넘어 이어진다

이 책의 패턴 번호는 장별로 리셋되지 않고 1번부터 32번까지 이어집니다. 10장은 새 패턴을 소개하지 않고 앞선 아홉 개 장의 패턴 21개를 이름으로 호출합니다.

→ 어느 패턴이 무엇이었는지는 이 덱의 「불려 나오는 패턴」 표를 보세요.
💡 이 저장소의 덱에서는 패턴 번호가 나올 때마다 몇 장의 것인지 함께 적어 두었습니다 — 예: 패턴 28(8장), 패턴 17(6장).
스크린샷을 번역하지 않은 이유를 명시해 둔 대목입니다.

📋 10.2 요약

이 장에서는 이 책 전체에서 다룬 설계 패턴들을 통합해 프로덕션급 에이전트 애플리케이션을 만드는 법을 보여 주었다.

1단순하고 조립 가능한 패턴 위에서, 교육용 콘텐츠를 만드는 AI 보조 또는 완전 자동 워크플로를 구성하는 법
2애플리케이션을 코파일럿(AI 보조) 모드와 에이전트(자율) 모드 양쪽으로 실행하는 것
3지속적인 학습 프로그램을 통해 코파일럿 모드를 시간이 갈수록 더 자율적으로 만들어 가는 것
4설치 과정, LLM 설정, 로깅 설정
5핵심 아키텍처 구성 요소 — 개별 에이전트, 멀티에이전트 오케스트레이션, 입력 가드레일, 학습 파이프라인의 결정적 역할, 튼튼한 데이터 프로그램의 중요성
생성형 AI는 흥미롭고 강력한 기술이며
이 책에서 다룬 패턴들은 그것을
현실의 유스케이스에서 실용적이고 쓸 만하게 만들어 준다
