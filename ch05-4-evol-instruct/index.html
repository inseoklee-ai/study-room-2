5.5.1 문제

모델 제공사는 여러분의 과제를 모른다
사전학습 모델이 많은 과제를 하도록 학습됐다고는 해도, 그 과제들은 모델 제공사가 예상했거나 소비자용 애플리케이션에서 마주친 것들에 치우칩니다.

🍣 하이쿠는 되는데 타당성 보고서는

✅ 하이쿠를 써 달라

충분히 많은 사람이 요청해 와서 모델의 학습 지시문에 포함됐고, 학습 코퍼스에 하이쿠 예시가 충분했다

❌ 창고 타당성 보고서를 써 달라

제공사가 그런 보고서가 어떤 모습이어야 하고, 어떤 절을 담아야 하며, 어떤 측면을 다뤄야 하는지 알까? 필요한 평가를 뒷받침할 데이터를 갖고 있을까?

엔터프라이즈 과제는 전혀 다른 문제다
💡 대개 공개 데이터로 학습시킬 수 있는 과제들만 담깁니다. 어떤 상업용 부동산이 자사 제품의 창고로 적합한지 판단하는 일 같은 건 그렇지 않죠.
5장 서론의 투자위원회 메모, 사내 조사 판정과 같은 계열의 문제입니다.

🔒 데이터 프라이버시라는 역설

Azure OpenAI의 약속 (일부)

귀사의 프롬프트(입력)와 컴플리션(출력), 임베딩, 학습 데이터는:

  • 다른 고객에게 제공되지 않습니다
  • OpenAI에 제공되지 않습니다
  • OpenAI 모델 개선에 사용되지 않습니다
  • Azure OpenAI Service 파운데이션 모델의 학습·재학습·개선에 사용되지 않습니다

Anthropic과 Gemini도 비슷한 정책을 갖고 있고, 많은 기업은 Google Distributed Cloud나 Azure Government 같은 에어갭 온프레미스 환경에서 씁니다.

이 모든 것은 —
모델 제공사가 엔터프라이즈 사용자가 무슨 과제를 시키는지
모른다는 뜻이다
⚠️ 설령 과제 목록을 얻는다 해도 두 번째 문제가 있습니다 — 엔터프라이즈 사용은 대개 제공사가 접근할 수 없는 기밀 데이터를 수반하므로 학습시킬 수가 없습니다.
💡 역설 — 이 요구는 엔터프라이즈 도입을 촉진하는 데 필요하지만, 동시에 (소비자 사용과 달리) 모델이 시간이 지나도 자동으로 잘하게 되지 않는다는 뜻이기도 합니다.
소비자용 ChatGPT는 쓸수록 좋아지지만 엔터프라이즈 모델은 그렇지 않습니다. 그게 이 패턴이 필요한 이유예요.

네 단계 — 4단계부터 거꾸로 읽기
1~3단계는 데이터셋 생성에 관한 것이라, 저자는 4단계(무엇을 위해 만드는가)부터 설명합니다.

📏 네 단계

1지시문
진화
→
2답 생성
→
3평가 · 필터링
→
4인스트럭션
튜닝
💡 4단계부터 시작하는 이유 — 사후 학습이 어떻게 작동하는지 알아야 커스텀 데이터셋에 무엇이 필요한지 이해할 수 있기 때문입니다.

④ 인스트럭션 튜닝 (SFT, supervised fine-tuning)

입력(프롬프트와 컨텍스트)과 출력(이상적 응답)으로 이루어진 시연 예시를 보여 준다. 새 유형의 과제를 가르치려면 그런 입력-출력 쌍의 데이터셋을 만들고 SFT를 하면 된다.

{"instruction": "Explain the concept of supervised learning.",
 "response": "Supervised learning is a machine learning
              paradigm where models learn from labeled..."}
📊 규모의 차이 — Adapter Tuning은 수백 개로 가능하지만, 인스트럭션 튜닝은 보통 수천 개가 필요합니다.
이 규모 차이가 1단계 "진화"가 필요한 이유입니다. 수천 개를 손으로 쓸 수는 없으니까요.

💻 ④ SFT — 오픈 웨이트 모델에서

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3-8b-hf", torch_dtype=torch.bfloat16)

# 흔한 요구사항 — 생성 중단을 알리는 특수 토큰으로 끝나는 단일 문자열
def format_and_tokenize(example):
    return tokenizer(
      f"### Instruction:\n{example['instruction']}\n\n"
      f"### Response:\n{example['response']}" + tokenizer.eos_token)

training_args = TrainingArguments(
    learning_rate=2e-5,      # 파국적 망각 때문에 낮게 (보통 1e-5 수준)
    num_train_epochs=3)      # 실제로 배우려면 여러 에폭이 필요
⚠️ 긴장 관계 — 파국적 망각 때문에 학습률은 낮아야 하지만, 모델이 과제를 실제로 배우기를 원하므로 여러 에폭이 필요할 수 있습니다.
💡 모델·트레이너·하드웨어가 지원하는 메모리 최적화(양자화, 그래디언트 누적 등)는 활용해야 합니다.
이 긴장이 인스트럭션 튜닝의 본질적 어려움입니다. 많이 가르치면 많이 잊어요.

🔧 PeFT로 하려면 — 세 가지 수정

최근의 혁신 덕분에 LoRA는 Adapter Tuning을 넘어서도 잘 작동한다. 다만 Unsloth가 제안하는 표준 LoRA 수정이 필요하다.

1새 과제가 원래 모델이 학습한 것과 비교해 "분포 밖(out of distribution)" 데이터를 수반할 수 있으므로, 모델뿐 아니라 임베딩 토큰과 어텐션 헤드도 함께 학습
2업·다운 프로젝션 층만 최적화하는 것으로는 부족했다 — 게이트 프로젝션(gate projection) 층도 함께 튜닝해야 했다
3임베딩 층과 선형 층에 서로 다른 학습률을 써야 했다
target_modules = ["q_proj", "k_proj", "v_proj", "o_proj",
                  "gate_proj",              # ②
                  "up_proj", "down_proj",
                  "embed_tokens", "lm_head"]  # ①

learning_rate           = 5e-5*2    # ③ 선형 층
embedding_learning_rate = 5e-5/2    # ③ 임베딩 층 — 4배 차이
💡 이 변경들을 적용하면 인스트럭션 튜닝에도 파라미터 효율적 접근을 쓸 수 있습니다.
패턴 15의 어댑터 설정과 비교하면 target_modules가 훨씬 넓습니다. 가르칠 게 더 많으니까요.

② 답 생성 — 다섯 갈래

지시문만으로는 부족하다. 그에 대한 올바른 응답이 함께 필요하다. 만들어 낸 질문들의 답은 어디서 구할까?

방법내용
사람 전문가제공사는 좋은 답을 쓰는 사람을 고용한다. 예산이 있다면 도메인 전문가에게 비용을 지불하라. 어떤 도메인에서는 크라우드소싱도 통한다
업계 도구시뮬레이터 · 매핑 도구 등 답을 만들어 낼 수 있는 소프트웨어. 사람 전문가에게 이 도구를 제공해 더 효율적으로 답하게 할 수도
평가를 루프에
리플렉션		모델이 답을 생성 → 평가자에게 → 오류를 돌려보내 재시도. 세 번 시도해도 안 되면 그 지시문을 버린다. 자동 평가자가 있을 때 잘 통한다 — 코딩이면 컴파일·샌드박스 실행, 수학이면 결과를 방정식에 대입
RAG기업 DB에 RAG를 적용해 생성. 다만 RAG 시스템이 이미 있다면 왜 모델을 학습시키나? → 추론 시점에 RAG가 불가능할 때(엣지, 데이터 접근 불가 환경) 그 지식을 사실상 모델 안에 "저장"
교사-학생강력한 "사고" 모델에게 답을 생성하게 한 뒤, 더 비용 효율적이고 지연이 낮은 모델을 파인튜닝. 증류(8장 패턴 24)와 비슷하지만, 증류는 보통 교사의 능력 전부를 복제하려 한다
💡 세 번째가 자동화 가능한 유일한 길입니다 — 그래서 코딩·수학 도메인에서 이 패턴이 특히 잘 작동합니다.
여러분 도메인에 자동 평가자가 있는지가 이 패턴의 비용을 좌우합니다.

5.5.3 예제

경영 전략 컨설턴트
현실에서는 기밀 데이터로 학습시키겠지만, 재현 가능해야 하므로 공개 데이터를 씁니다.

🎯 목표 — 10억 파라미터로 Claude에 필적

질문 — 모건 스탠리의 초고액 자산가 시장 전략

✅ Claude Sonnet 3.7

… 기관 전문성에 대한 확립된 평판과 기존의 밀착 관계가 강점이나, 더 공격적인 가격과 혁신적 디지털 서비스에는 고전할 수 있다. 개인화된 다세대 자산 계획에 집중하고 특화된 대체 투자 상품을 확대하며 …

❌ Gemma 3 1B

… 기존의 글로벌 네트워크를 활용해 유치·유지하고 맞춤형 서비스를 제공할 수 있다. 그러나 경쟁사의 치열한 경쟁으로 상쇄되어 … 강화된 실사와 프리미엄 서비스를 우선하는 한편 …

🍔 일반론적 답의 표식 — 치환 테스트
Gemma의 답에서 모건 스탠리 → 맥도날드, 자산관리 서비스 → 햄버거로 바꿔 보라. 대부분 그대로 말이 됩니다.
💡 Claude는 다세대 자산 계획 같은 구체적 영역을 짚습니다 — 밀착 관계가 필요하고 가격 민감도가 낮으며 기술적 정교함에 덜 매료되는 시장이라는 걸 아는 거죠. 다만 우리는 고객 확보와 유지를 물었는데 권고는 회사 전반의 포지셔닝에 관한 것입니다.
치환 테스트가 실무에서 바로 쓸 수 있는 진단법입니다. 회사 이름을 바꿔도 말이 되면 내용이 없는 겁니다.

Air Products (APD) — 화학 회사

Air Products(APD)는 가스화, 탄소 포집, 수소 프로젝트에 대규모로 투자하고 있다. 에너지 시장의 순환적 성격은, 특히 회사가 장기 계약과 고객 관계에 의존하는 2021년 시점을 고려할 때, 이 자본 집약적 프로젝트들의 장기 수익성과 전략적 존립 가능성에 어떤 영향을 줄 수 있는가?

💡 좋은 질문입니다! 답이 뭔지는 모르겠지만 — Air Products의 경영진이 이를 고민했고 SEC 공시에 자기들의 답을 적어 뒀다는 점이 훌륭합니다.
질문은 공시에서 뽑고
답도 같은 공시에 있다

📝 정리본은 여기서 끊깁니다. 진화 결과와 최종 튜닝 성능은 원문 정리본에 담겨 있지 않습니다.
