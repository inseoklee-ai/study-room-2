2.1.1 문제

규칙은 있는데 강제할 수단이 없다
LLM으로 텍스트를 생성할 때 그 텍스트가 특정 스타일 규칙을 따르길 원하는 경우가 있습니다. 브랜딩·정확성·컴플라이언스 등의 이유로요.

📝 어떤 규칙들인가 — 책의 네 예시

종류내용
브랜딩
Branding		제품 A를 이야기하면 그 브랜드 단어(스포티한, 고성능의)를 쓰고 제품 B의 단어(널찍한, 고급스러운)는 쓰지 않는다
정확성
Accuracy		청구서에서 인보이스 ID와 금액이 본문에서 반복되지 않게 한다. 검증은 정해진 위치의 값에 대해서만 이뤄지므로 반복은 오류 가능성을 높인다
컴플라이언스
Compliance		고객사 A의 사례 연구를 언급할 때 경쟁사 B·C·D 언급이 들어가지 않게 한다 — 인용 허락이 "직접 경쟁사가 없는 콘텐츠"에 한정됐을 수 있다
스타일북
Stylebook		시카고 매뉴얼 오브 스타일, APA 인용 방식 등
💡 공통점 — 전부 프로그램으로 판정 가능한 규칙입니다. 그래서 강제할 수 있습니다.
정확성 예시가 특히 흥미롭습니다. "같은 정보를 두 번 말하지 마라"는 규칙은 스키마로 표현할 수 없어요. 이미 생성된 내용에 따라 달라지는 동적 규칙이라 패턴 2가 아니라 패턴 1의 영역입니다.

이 방식은 재생성이 필요한 응답이 아주 적을 때(10% 남짓)만 통한다. 그렇지 않으면 재시도가 지연을 극적으로 늘리고, 때로는 수용 가능한 답으로 수렴조차 하지 않는다.

📈 시도 횟수는 기하분포를 따르므로 평균과 테일 레이턴시를 계산할 수 있습니다. 성공률이 p%라면 평균 생성 횟수 = 100/p.
비유하자면 작문 시험에서 금지어가 있을 때, 학생이 글을 다 쓴 다음 검사해서 금지어가 있으면 처음부터 다시 쓰게 하는 겁니다.

📊 숫자로 보면 무섭다

성공률평균 시도평균 지연최악 (99분위)
90%100/90 ≈ 1.1회+10%2회
30%100/30 ≈ 3.3회+230%13회
⚠️ 성공률 30%면 운 나쁜 사용자는 13번을 기다립니다. 한 번에 2초라면 26초. 게다가 영원히 성공 못 할 수도 있습니다.
  • 99분위수에는 닫힌 공식이 없다 — 기하분포에서 수치적으로 추정해야 한다
  • 지수 백오프를 쓰면 지연 증가는 더 커진다
  • 허용 시도 횟수를 줄이면 애플리케이션의 거부율이 올라간다
"될 때까지"는 성공률이 아주 높을 때만 받아들일 만하다
이 표가 패턴 1이 왜 필요한지를 가장 설득력 있게 보여줍니다. 성공률이 조금만 떨어져도 재앙이 돼요.

2.1.2 해법

샘플링 단계에서 가로챈다
1장의 빔 서치에서 봤듯 파운데이션 모델은 가능한 연속의 시퀀스에서 표집합니다. 아이디어는 바로 그 표집 단계에서 생성을 가로채는 것입니다.

🔧 어디서 개입하는가

마지막 층 → 로짓(원시 점수) → [여기] → 소프트맥스 → 확률 → 표집
P(token_i) = exp(logit_i) / Σ_j exp(logit_j)

exp(-∞) = 0   →   금지 토큰의 로짓을 -inf로 만들면
                  확률이 정확히 0. 0.001%가 아니라 진짜 0.
💡 1장에서 "언어 모델은 어떤 후속 단어라도 확률이 0이 되지 않는 표집 전략을 쓴다"고 했는데, 로짓 마스킹은 그 원칙을 의도적으로 깨는 것입니다.
🔧 구현 팁 — torch는 -np.inf를 싫어하므로 실무에선 -10000을 씁니다.
학생이 단어 하나 쓸 때마다 옆에서 보고 있다가 금지어를 쓰려 하면 펜을 막아 다른 단어를 쓰게 하는 겁니다. 다 쓰고 검사하는 것보다 훨씬 효율적이죠.

📏 다섯 단계

1샘플링 가로채기 — 전부 생성될 때까지 기다리지 않고 각 중간 지점에서 가능한 연속 집합을 얻는다
2유효하지 않은 시퀀스를 0으로 — 규칙에 안 맞는 연속의 확률을 0으로 만든다
3표집 — 규칙에 맞는 연속이 하나라도 있으면 생성을 계속한다
4최대 시도 초과 판단 — 넘기면 거부 응답을 사용자에게 보낸다
5백트래킹과 재생성 — 맞는 연속이 하나도 없거나 막다른 길이면 한 단계 되돌아가 다시 생성한다
🎯 효과는 빔 서치에서 규칙에 안 맞는 빔을 쳐내는 것입니다.

①②③ 시퀀스 선택

걸러내도 쓸 만한 게 남는 경우. 남은 것 중 고르면 끝. 단순한 유스케이스에 충분.

④⑤ 시퀀스 재생성

걸러내면 후보가 하나도 안 남는 경우. 뒤로 되돌아가야 한다.

그림 2-2의 회색 실선 상자가 시퀀스 선택, 빗금 상자가 시퀀스 재생성입니다. 뒤의 두 예제가 정확히 이 둘이에요.

💻 구현 — Transformers

1단계 · 2단계 — LogitsProcessor 서브클래스
class MyRulesLogitsProcessor(LogitsProcessor):
    def __init__(self, tokenizer, rules):
        self.tokenizer = tokenizer; self.rules = rules

    def __call__(self, input_ids, input_logits):
        output_logits = input_logits.clone()
        for idx, input_id in enumerate(input_ids):
            seq = self.tokenizer.decode(input_id)   # 토큰 ID → 문자
            if not self.apply_rules(seq, self.rules):
                output_logits[idx] = -np.inf        # 확률을 0으로
        return output_logits
3단계 — 파이프라인에 넘긴다
results = pipe(input_message, max_new_tokens=256, do_sample=True,
               temperature=0.8, num_beams=10,
               logits_processor=[rules_processor])
⚠️ 두 가지 주의 — ① 입력은 자연어가 아니라 토큰 ID라 디코딩이 필요하다 ② 로짓은 확률의 로그이므로 0으로 만들려면 음의 무한대로 둔다
num_beams가 중요합니다. 후보가 하나면 걸러낼 때 고를 게 없어요. 빔이 여러 개여야 마스킹이 의미가 있습니다.

↶ 5단계 — 백트래킹은 직접 짜야 한다

Transformers의 파이프라인 호출은 백트래킹과 재생성을 허용하지 않는다. 그러려면 생성 루프 전체를 직접 통제해야 한다.

results = pipe.model.generate(
            **input_ids,
            max_new_tokens=16,      # 정해진 토큰 수씩 끊어서
            num_beams=10, output_scores=True)
input_ids = pipe.tokenizer(
    input_prompt + '\n'.join(text_so_far),   # 이전 생성분을 이어 붙인다
    return_tensors="pt").to("cuda")
  • 루프에는 (재)초기화 · 규칙 적용 · 백트래킹 · 중지 로직이 들어간다
  • 상태 변수를 유지해야 한다
  • 중지는 흔히 중지 문자열(stop string)로 — 프롬프트 지시나 예시에 포함시킨다
generate를 16토큰씩 끊어 부르면서 매번 규칙을 검사하고, 막히면 앞으로 되돌아가는 구조입니다. 파이프라인 한 방으로는 안 돼요.

2.1.3 예제

A 시퀀스 선택 · B 시퀀스 재생성
예제 A는 1~3단계만으로 되는 단순한 문제, B는 1~5단계가 모두 필요한 복잡한 문제입니다.

📦 예제 A — 시퀀스 선택 (단백질 음료)

영양 보조제 마케터. 이커머스 상품 페이지는 수상 경력(award winning) 같은 표현을 거부하는 경향이 있고, SEO 분석으로 넣으면 좋은 표현은 알고 있다.

제로샷 결과 — 규칙 위반

PowerBoost를 소개합니다 … 가장 힘든 운동 후의 근육 성장(growth)과 회복을 돕습니다. 고품질(quality) 유청 단백질과 필수 비타민으로 만든 PowerBoost는 … 재충전하는 완벽한(perfect) 방법입니다.

좋은 SEO 용어 두 개(whey, whey protein)는 들어갔지만 차단 확률을 높이는 단어 세 개도 함께 들어갔습니다. high-quality와 muscle growth는 무해해 보이지만 — 왜 위험을 감수하겠는가?
SEO 키워드는 MarketKeep이 Google Ads 키워드 플래너로 만든 영양 관련 상위 키워드 집합을 썼습니다.

✅ 예제 A — 마스킹 적용

def evaluate(descr, positives, negatives) -> int:
    descr = descr.lower()
    num_positive = np.sum([1 for p in positives if p in descr])
    num_negative = np.sum([1 for n in negatives if n in descr])
    return int(num_positive - num_negative)   # 점수 = 희망어 − 금지어
# 최댓값이 아닌 시퀀스를 마스킹한다

2.1.4 고려사항과 대안

대안 · 확장 · 주의점
LLM의 기계 장치 대부분을 그대로 쓰면서 표집에만 내 선호를 강제하는 방법입니다. 허용되지 않는 선택지를 쉽게 걸러낼 수 있을 때 유용해요.

🔁 다섯 가지 대안

대안언제 · 한계
퓨샷 예시 (패턴 3)
프롬프트 엔지니어링		더 간단하다. 다만 엄격한 강제 수단이 아니다 — 규칙을 따를 거라 확신할 수 없다
더 강력한 모델지시를 더 잘 따른다. 추론 모델은 스스로 철회·재생성한다. 다만 더 비싸고 느리다
될 때까지 다시 해 보기규칙 준수 확률이 충분히 높으면 합리적. p = 0.9면 99분위수가 겨우 2회
성찰 (패턴 18)로짓 마스킹은 재생성 때 아무 힌트도 주지 않는다. 규칙 엔진이 유용한 오류 메시지를 준다면 프롬프트를 그것으로 갱신 → 시도 횟수를 줄인다
문법 (패턴 2)규칙을 표준 형식으로 표현할 수 있다면 마스킹을 모델 제공자에게 떠넘길 수 있다
마지막 줄이 패턴 2로 넘어가는 다리입니다. 형식으로 표현 가능하면 굳이 직접 할 이유가 없어요.

🔍 확장 — 자동완성

구글은 검색어 입력 중 완성을 제안한다. 그 제안은 "실제 검색과 웹 전반에서 발견된 단어 패턴"에 기반한다.

🔒 실제 검색 기록에 기반하려면 사용자 검색어를 로깅해야 하는데, 이는 다른 사용자가 무엇을 검색하는지 흘립니다. 배포 환경이나 개인 검색어로 한정하면 콜드 스타트가 대량 발생합니다.

그래서 단어 패턴만으로 구현하고 싶어진다. 색인을 만들 수도 있지만, 더 간단한 방법은 문서를 컨텍스트에 담아 둔 채 로짓 마스킹을 쓰는 것.

1입력 중인 질의를 한 구절이나 문장을 덧붙여 완성하도록 LLM에게 요청
2LogitsProcessor에서 상위 완성 후보 목록을 얻어 사용자에게 보여 준다
3후보를 고르면 시퀀스 선택으로 나머지를 0으로 / 다른 구절을 입력하면 그것을 출발점으로 시퀀스 재생성
💡 실제 구현에서는 문서 전체를 컨텍스트에 캐싱해, 질의마다 입력 토큰 비용을 내지 않고 전체 지식 베이스에 접근하게 합니다.
이건 규칙이 사용자 입력에 의존하는 경우라 패턴 2로는 못 합니다. 동적이니까요.

  • 검열 방식이라는 성질 — 규칙을 만족하는 후보가 없으면 유효한 콘텐츠를 못 만든다. 그래서 프롬프트에 충분한 정보를 담는 것이 중요하다
