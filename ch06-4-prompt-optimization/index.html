6.4.2 해법

한 겹의 간접 계층
소프트웨어 공학의 근본 정리라는 유명한 격언이 있습니다. 어울리게도 그 기원 자체가 복잡해요.

💡 소프트웨어 공학의 근본 정리

"컴퓨터과학의 모든 문제는
한 겹의 간접 계층을 더하면 풀 수 있다"
📜 기원 자체가 복잡합니다 — 프로그래머 Andrew Koenig이, 컴퓨터과학 선구자 Butler Lampson이 David J. Wheeler 교수의 말이라고 밝힌 인용구를 지칭하며 만든 용어입니다.

모든 문제는 아닐지 몰라도, 주어진 LLM 버전에 맞게 프롬프트를 최적화해야 하는 문제는 확실히 간접 계층 하나로 풀 수 있는 문제다.

기존코드에
프롬프트가 박힘
→
간접 계층프레임워크가
프롬프트를 주입
→
결과모델이 바뀌면
다시 돌리기만
그 간접 계층이 DSPy 같은 프레임워크입니다.

🧩 네 구성 요소

구성 요소레시피 비유내용
파이프라인요리 공정 순서입력을 받고, 필요에 따라 모델(과 도구)을 호출하고, 출력을 반환. 프레임워크가 각 단계에 필요한 프롬프트를 주입한다
데이터셋시험 삼아 구워 볼 재료 묶음입력과 참조 답안의 쌍(지도 학습용)이거나 입력만. 예제 하나만큼 작아도 된다 — 그러면 그 입력 하나에 대한 최적 프롬프트를 얻는다
평가자맛 채점표결과를 자동으로 평가. 참조 답안과 비교하거나, 적합도 점수를 계산(패턴 17처럼. 참조 답안이 없을 때 유용)
옵티마이저시험 주방장여러 프롬프트 변형을 생성하고 데이터셋에 대해 실행해 최적화된 파이프라인을 반환. 입력 파이프라인 그 자체이되 각 단계마다 가장 잘 동작한 프롬프트가 채워진 것
📑 평가자 자리에 패턴 17이 들어갑니다 — 이 장의 패턴들이 서로 물려 있는 지점입니다.
데이터셋이 예제 하나여도 된다는 게 진입 장벽을 크게 낮춥니다.

6.4.3 예제

뒤표지 블러브 — DSPy
O'Reilly 책 뒤표지 정보를 개선합니다. 오늘날 그 설명들은 저자들이 쓴 초안에 기반하는데, 저자들은 자기 책의 마케터로서는 대개 형편없죠.

① 시그니처 — 프롬프트를 쓰지 않는다

lm = dspy.LM("claude-3-7-sonnet-latest", api_key=...)
dspy.configure(lm=lm)
# 1단계 — 추출
class BlurbExtraction(dspy.Signature):
    text: str = dspy.InputField(desc="Text from backcover")
    blurb: Blurb = dspy.OutputField(desc="Extracted information")

class Blurb:
    about_topic: str = Field(description="Why the topic is worth learning")
    about_book: str = Field(description="What book contains")
    target_audience: List[str] = Field(description="Roles such as...")
    learning_objectives: List[str] = Field(description="""4-6 objectives
        that complete the sentence: You will learn how to ___""")
💡 변수 이름에 담을 수 있는 것보다 더 많은 정보를 주려면 설명 문자열로 초기화합니다. 프롬프트 문장은 어디에도 없습니다.
module = dspy.ChainOfThought(BlurbExtraction)   # CoT 모듈 자동 생성
orig_cover_info = module(text=mldp_text)
블러브는 엄밀히는 칭찬 인용문만 가리키지만, 여기서는 뒤표지 정보 전체를 가리키는 말로 씁니다.

② 두 단계를 하나의 모듈로

# 2단계 — 개선. 각 필드의 설명이 "LLM이 해야 할 일"을 담는다
class BlurbImprovement(dspy.Signature):
    current_cover: Blurb = dspy.InputField(...)
    about_topic: str = dspy.OutputField(desc="""More catchy statement""")
    target_audience: List[str] = dspy.OutputField(desc="""more aspirational
        list of roles. Instead of programmer, say software engineer.
        Restrict to top 3.""")
    learning_objectives: List[str] = dspy.OutputField(desc="""rephrased or
        reordered to be more appealing. Exactly 6.""")
class BlurbPipeline(dspy.Module):
    def __init__(self):
        self.extract_info = dspy.ChainOfThought(BlurbExtraction)
        self.improve_blurb = dspy.ChainOfThought(BlurbImprovement)

    def forward(self, in_text: str) -> (Blurb, Blurb):
        cover_info = self.extract_info(text=in_text)
        improved_cover = self.improve_blurb(
                             current_cover=cover_info.blurb)
        return cover_info.blurb, make_blurb(improved_cover.toDict())
💡 두 단계를 하나로 묶는 이유 — 두 단계를 함께 최적화할 수 있게 하기 위해서입니다. forward()가 첫 단계의 출력을 두 번째 단계의 입력으로 넘깁니다.
패턴 19의 체인과 구조가 같습니다. 다만 여기서는 프레임워크가 최적화까지 맡아요.

④ 평가자 — 참조와 비교하기

⚠️ 구성 요소마다 채점 기준을 만들 수도 있지만, 패턴 17에서 이것이 상당히 관대하다는 걸 이미 압니다. 한 블러브가 0.89, 다른 것이 0.90이면 그 개선을 믿기 어렵습니다 — 각 블러브를 따로따로 평가했을 때 실제로 벌어진 일입니다.
그래서 — 원본을 참조 블러브로 주고

class BlurbScore(dspy.Signature):
    reference_blurb: Blurb = dspy.InputField()
    blurb_to_evaluate: Blurb = dspy.InputField()
    topic_score: float = dspy.OutputField(desc="""-1 to 1: how much
        more appealing the topic description is, as compared to reference""")
    contents_score: float = dspy.OutputField(desc="""-1 to 1: ...""")
    objectives_score: List[float] = dspy.OutputField(desc="""-1 to 1: ...""")
💡 척도가 0~1이 아니라 −1~1입니다 — "얼마나 좋은가"가 아니라 "참조보다 얼마나 나은가"를 묻습니다. 관대함을 우회하는 설계예요.
패턴 17의 "직접 비교시키기" 권고를 그대로 구현한 겁니다.

📊 점수 집계 — 길이에 벌점

def calc_aggregate_score(blurb: Blurb, p: dspy.Prediction) -> float:
    result = (p.topic_score * 10 +
              p.contents_score * 10 +
              sum(p.objectives_score)) /
              (20 + len(p.objectives_score))

    ## MAX_LINES 를 넘는 줄마다 0.1 씩 깎는다
    num_lines = len(blurb.toMarketingCopy().splitlines())
    if num_lines > TARGET_MAX_LINES:
        result -= 0.1 * (num_lines - TARGET_MAX_LINES)
    if result < 0: result = 0
    return result
💡 길이 벌점이 들어간 이유 — 패턴 17의 길이 편향(LLM은 긴 것을 선호) 때문입니다. 평가자가 못 잡는 것을 집계 함수에서 잡는 것이죠.
재작성본의 적합도 점수 0.63
원본에 비해 상당한 개선
주제와 내용에 가중치 10씩, 학습 목표는 개수만큼. 설계 의도가 드러나는 식입니다.

생성된 추론

현재의 표지 정보는 탄탄하지만 더 설득력 있게 만들 수 있다.
1. 디자인 패턴이 경쟁 우위를 준다는 점을 강조해 "about topic"을 더 긴박하고 흥미롭게
2. 내용의 실용적이고 변혁적인 성격을 부각
3. 대상 독자 서술을 더 열망적인 직함으로 격상
4. 학습 목표를 단순한 기술 습득이 아니라 경력 발전과 실질적 성과를 강조하도록 재구성

모델이 자기 계획을 먼저 세우고 실행합니다. 5장 패턴 13이 여기 들어가 있는 셈이죠.

⑤ 두 가지 최적화 방식

① Best-of-N — 블러브 하나로

optimized_pipeline = dspy.BestOfN(
    module=BlurbPipeline(), N=10,
    reward_fn=score_reward, threshold=0.95)

10회 반복에서 멈추거나 임계 성능(0.95)에 도달하면 멈춘다. 시행 사이의 변주는 CoT의 추론 문자열이 어떻게 구성되는가에 있다.

결과 0.74점 — 앞서의 0.63보다 높다. 문제 — 추론을 10번 돌려야 한다

② 퓨샷 옵티마이저 — 부트스트랩

예제가 10개 있다면 그중 3개를 예시로 뽑고, 이 프롬프트가 나머지 7개에서 얼마나 잘 동작하는지 평가한다. 매번 다른 3개 조합을 골라 가며 부트스트랩하고 가장 잘 동작하는 프롬프트를 고른다.

optimizer = BootstrapFewShot(metric=evaluate_blurb)
optimized_pipeline = optimizer.compile(BlurbPipeline(),
                                       trainset=blurbs)
optimized_pipeline.save("optimized_pipeline", save_program=True)
💡 차이 — Best-of-N은 쓸 때마다 10번 구워야 하고, 퓨샷은 레시피 자체를 확정해 두어 실제로 쓸 땐 한 번만 구우면 됩니다.
여러 권의 책에 대해 설명문을 개선하고 싶다면 두 번째가 답입니다.

⚠️ 6.4.4 — 프롬프트 라이브러리로는 안 되는 이유

🚫 순진한 해법 하나는 프롬프트 라이브러리입니다 — 모든 프롬프트를 설정 파일로 외부화하면 바꾸기가 쉬워집니다. 그러나 이런 프롬프트 관리는 핵심 문제를 풀지 못합니다. 핵심 문제란 의존성이 바뀔 때마다 여전히 손으로 실험을 다시 해야 한다는 것입니다.
✅ 물론 프롬프트 관리와 버전 관리는 좋은 실천입니다. 다만 Prompt Optimization이 더 포괄적인 해법을 제공하기에 패턴으로 따로 싣지 않았을 뿐입니다.

🔄 한 걸음 더 나간 변형과 그 한계

시도한 모든 프롬프트 반복을 저장해 두고 프레임워크가 다음 버전 LLM에서 그 단계들을 반복하게 할 수도 있다. 그런 다음 결과를 살펴보고(혹은 자동 평가자로) 가장 잘 동작하는 프롬프트를 고른다.

문제 — 애플리케이션이 바뀌면 옛 프롬프트도 함께 갱신해야 한다(변수를 추가·제거하는 식으로). Prompt Optimization 쪽이 유지보수 부담이 훨씬 적다.

프롬프트를 밖으로 빼는 것과 자동으로 만드는 것은 다른 이야기입니다.

🚀 확장 — 데이터가 쌓이면

best-of-N이나 퓨샷에 한정되지 않는다. 데이터셋에 예제가 수천 개 있다면 DSPy로 이 특정 파이프라인을 위해 LLM을 파인튜닝할 수도 있다.

Prompt Optimization은
가장 기초적인 단계인 경우가 많다
1모든 프롬프트와 사람의 피드백을 기록하는 인프라를 갖춘다
2그것을 데이터셋으로 내보내, Prompt Optimization으로 평가 프롬프트(패턴 17)를 만든다
3패턴 17이 확장 가능한 평가를 열어 준다
4수집된 프롬프트(사람 피드백이 없는 것까지)로 특정 과업에 맞춰 LLM을 사후 학습시킬 데이터셋을 만든다
📑 4단계가 5장 패턴 15·16으로 이어집니다 — 이 패턴이 데이터 수집 인프라의 출발점 역할을 합니다.
