> **한 줄 요약** — 모델은 뛰어나지만 믿을 수 없다. 그 간극을 메우는 검증된 해법 32가지를 모은 것이 이 책이다.

- ✅ **1장 (1/2) 프로토타입은 쉽고 프로덕션은 어렵다** — 설계 패턴 · 프롬프트와 컨텍스트 · 기초 모델 제작 과정 · 모델 지형도
  🖥️ [웹 슬라이드](https://inseoklee-ai.github.io/study-room-2/ch01-1-patterns-and-models/) (25장)
- ✅ **1장 (2/2) 에이전트, 그리고 모델을 내 쪽으로 당기는 법** — 에이전트형 AI · 세밀한 제어 · 컨텍스트 내 학습 · 사후훈련 · 책 전체 지도
  🖥️ [웹 슬라이드](https://inseoklee-ai.github.io/study-room-2/ch01-2-agentic-and-control/) (29장)
- 📑 [1장 텍스트 학습노트](notes/ch01.md) — 요약 · 표 · 코드 · 자가점검 13문항
- 💬 [1장 토론노트](notes/ch01-discussion.md) — **책에 답이 없는 여섯 질문** (온도 0의 재현성 · Top-K/P 충돌 · 프롬프트 vs 미세조정 · 위임의 경계 · 빔 탐색이 맞는 작업 · 우리 시스템에 급한 장)

<details>
<summary><b>1장 핵심 정리 펼치기</b></summary>

**문제** — 생성형 AI는 프로토타입이 쉽고 프로덕션이 어렵다. 환각·비결정성은 버그가 아니라 **훈련 방식에서 오는 고유 성질**이다.

**형식** — 반복되는 문제의 검증된 해법에 이름을 붙인 것이 **설계 패턴**(32개). 이득은 ① 공통 어휘 ② 품질·유지보수성·확장성.

**재료** — 기초 모델은 `사전훈련 → SFT → 강화학습`으로 만들어진다. 모델은 **프런티어 · 증류 · 가중치 공개 · 로컬** 네 부류.

**목표** — 에이전트의 네 특징: 목표 지향성 · 계획 및 추론 · 인지 및 행동 · 적응 및 학습. 단 **아직 완전히 실현되지 않았다.**

**수단 — 세 개의 레버 (싼 것부터)**

| 레버 | 바꾸는 것 | 비용 |
|---|---|---|
| 세밀한 제어 | 초매개변수 (온도 · Top-K/P · 벌점) | 거의 0 |
| 컨텍스트 내 학습 | 프롬프트 (예시 · 지시사항) | 낮음 |
| 사후훈련 | 가중치 (SFT · LoRA · DPO) | 높음 |

> **1장이 남기는 태도 — 모델을 믿지 말고, 다룰 구조를 설계하라.**

</details>

### 🔨 2장 · 스타일과 형식 제어 — 진행 중

- 🔨 **패턴 1 로짓 마스킹** — 📑 [개념 · 코드 해설 · CPU 실습 기록](notes/ch02-pattern01-logit-masking.md)
  예제 노트북 4개 중 **1개 완료** (`0_logits_masking` ✅ / `1_sequence_selection` · `2_sequence_regeneration` · `3_autocomplete` ⏳)

<details>
<summary><b>실습 결과 펼치기</b></summary>

프롬프트는 한 글자도 바꾸지 않고, **마스킹 여부만** 다르게 했을 때:

| | 점수 | 걸린 희망어 | 걸린 금지어 |
|---|---|---|---|
| v1 (마스킹 없음) | **−1** | 없음 | `complete` |
| v2 (마스킹 적용) | **+2** | `calorie`, `protein shake` | 없음 |

**환경** — Windows 11 · CPU 전용 · `Qwen/Qwen3.5-0.8B`(Llama에서 교체)

**실측 시간** — 모델 로딩 14초 / 마스킹 없는 생성 5분 16초 / 마스킹 + 4빔 2분 29초

**노트에 정리한 것** — 로짓 마스킹의 원리와 `BrandLogitsProcessor` 줄별 해설, 겪은 문제 6가지(`AssertionError`의 진짜 의미 · uv `.venv` 커널 · 한국어 윈도우 cp949 인코딩 · 노트북 메모리 상태 함정 · `set` 순서 비결정성), CPU에서 **bfloat16이 float32보다 4.5배 느린** 이유, 그리고 정직한 한계 5가지.

</details>

- 🔨 **패턴 2 문법** — 📑 [개념 정리 · 자가점검 6문항](notes/ch02-pattern02-grammar.md)
  예제 노트북 3개 **모두 예정** (`1_applying_grammar` · `2a_json_mode` · `2b_structured_data` ⏳) — **개념 정리만** 완료

<details>
<summary><b>패턴 2 핵심 정리 펼치기</b></summary>

**정체** — 패턴 1과 하는 일은 같다(안 맞는 후보의 확률을 0으로). 차이는 **누가 하느냐** — **모델 제공자가 서버 쪽에서** 대신 한다.

**문제** — "JSON으로 줘"라고 부탁하는 것은 ① 취약하고 ② 불안정하고 ③ 비싸다. 결정적 이유는 이것이다.

> **"LLM 호출을 소비하는 모든 쪽이, LLM이 지시를 안 따를 가능성에 대비해야 한다."**

**해법 세 가지** — 책의 예제 노트북 3개와 그대로 대응한다.

| | 방법 | 언제 | 난이도 |
|---|---|---|---|
| ① | **스키마 · dataclass** | **여기서 시작한다.** 실무 대부분이 여기서 끝난다 | 쉬움 |
| ② | JSON 모드 | "JSON이기만 하면" 될 때 | 아주 쉬움 |
| ③ | BNF 문법 | SQL·정규식처럼 **진짜 문법**이 필요할 때 | 어려움 |

**가장 큰 함정 — 문법이 정답을 막는다.** 책의 산술식 예제에서 문법에 `>`가 없어 모델은 *"사과가 오렌지보다 많나?"*에 **답하지 못했다.** 저자는 제약이 작동한 증거로 제시하지만, 뒤집으면 **문법 설계 실수가 그럴듯한 오답으로 나타난다는 뜻**이다. 그래서 항상 탈출구를 둔다.

```python
currency_rate: float | Literal["Unknown"]
```

**이름에 속지 말 것** — "구조화된 출력 지원"이 **제약 디코딩을 뜻하지 않는다.** 생성 후 LLM을 한 번 더 불러 형식을 맞추는 구현(책은 LangGraph를 지목)은 느리고 비싸고 여전히 틀릴 수 있다. Claude도 제약 디코딩 대신 **prefill**을 권한다.

</details>
