왜 설계 패턴인가

인상적인 데모와 신뢰할 수 있는 제품 사이의 거리

1.1 생성형 AI 설계 패턴
이 책의 존재 이유가 담긴 절입니다. 문제 정의가 정확해야 해법(패턴)이 왜 그 모양인지 이해됩니다.

💥 데모는 하루, 프로덕션은 반년

  • 생성형 AI는 강력하면서도 쉽다 — 비전문가도 인상적인 프로토타입을 만든다
  • 그런데 그 프로토타입을 프로덕션 수준으로 끌어올리기가 어렵다
  • 이유는 하나로 모인다 — 모델을 신뢰하기 어렵다

💀 환각(hallucination)

없는 사실을 확신 있게 지어낸다

🎲 비결정성

같은 입력에 매번 다른 답을 내놓는다

⚠️ 핵심은 이것이 버그가 아니라는 점입니다. 대부분 생성형 AI 고유의 훈련 방식에서 기인하므로 "고쳐서 없애는" 대상이 아니라 설계로 감싸 다뤄야 하는 성질입니다.
모니터링 에이전트를 만들 때 "조용히 실패하지 않기"가 중요한 것과 같은 맥락입니다. 모델의 불확실성을 없앨 수 없다면, 그것을 드러내고 다루는 구조를 짜야 합니다.

이 전환이 왜 중요하냐면, 할 수 있는 일과 할 수 없는 일이 통째로 달라지기 때문입니다. 가중치를 못 건드리니 프롬프트·컨텍스트·오케스트레이션이 주 무기가 되고, 그래서 "패턴"이 필요해집니다.

🏢 제공업체 API — 시스템 vs 사용자 프롬프트

import anthropic
client = anthropic.Anthropic()   # 생략 시 ANTHROPIC_API_KEY 환경변수 사용

completion = client.messages.create(
    model="claude-sonnet-4-5",
    system="당신은 파이썬 프로그래밍 전문가입니다.",        # ← 시스템 프롬프트
    messages=[{
        "role": "user",
        "content": [{"type": "text",
                     "text": "주어진 정수 목록의 중앙값을 구하는 코드를 작성하세요."}]
    }]                                                    # ← 사용자 프롬프트
)
print(completion.content[0].text)
구분역할성격
시스템 프롬프트모델의 전반적인 동작을 안내 (역할 · 톤 · 원칙)상대적으로 고정적
사용자 프롬프트이번에 수행할 구체적인 지시와 자료매 요청 동적
이 구분이 실무에서 중요한 이유: 시스템 프롬프트는 캐싱 대상이 되고(8장 프롬프트 캐싱), 가드레일을 걸어두는 자리이며(9장), 사용자 입력이 침범해서는 안 되는 경계이기도 합니다.

🔁 LLM 비종속 프레임워크 — 한 줄만 바꾸면 된다

from pydantic_ai import Agent

agent = Agent('anthropic:claude-sonnet-4-5',
              system_prompt="당신은 파이썬 프로그래밍 전문가입니다.")
result = agent.run_sync("주어진 정수 목록의 중앙값을 구하는 코드를 작성하세요.")
print(result.data)
제공업체를 바꾸려면 — 모델 식별 문자열만 교체
'anthropic:claude-sonnet-4-5'
'openai:gpt-4o-mini'
'google-vertex:gemini-2.0-flash'
'groq:llama3-70b-8192'
💡 클래스 이름이 Agent인 것에 주목 — 프레임워크는 이미 모델 호출을 "에이전트"로 부릅니다. (다음 덱 PART 1에서 이어집니다)
이 책이 특정 벤더에 묶이지 않으려 애쓴 이유이기도 합니다. 전작 『Machine Learning Design Patterns』가 텐서플로·GCP에 치우쳤다는 평을 받아서, 이번에는 여러 제공업체와 프레임워크를 섞어 씁니다. 코드 예제는 "시작점"으로만 삼으라는 것이 저자들의 당부입니다.

기초 모델은 어떻게 만들어지나

사전훈련 → 지도학습 미세조정 → 강화학습

1.2.5 · 딥시크 공개 정보 기준
2025년 봄 기준 훈련 방식이 가장 많이 공개된 모델이 딥시크입니다. GPT·제미나이·클로드·라마가 정확히 같지는 않겠지만 대체로 비슷하다는 것이 저자들의 설명입니다. 이 3단계를 알아야 뒤의 "사후훈련"이 이해됩니다.

🏭 모델 공장의 세 공정

다음 토큰 예측
→

인간 선호 정렬
단계얻는 능력재료
사전훈련일반적인 언어 이해 — 앞 토큰들을 보고 다음 토큰 예측방대한 말뭉치 14.8조 토큰
SFT지시를 따르는 능력 — 프롬프트에 대한 이상적 응답 모방사람이 쓴 선별된 예시
RLHF인간의 기대와 가치에 정렬결과물 쌍의 선호 판정
그래서 LLM을 "다음 토큰 예측기"라 부르지만, 그건 1단계일 뿐입니다. 우리가 쓰는 모델의 성격은 2·3단계에서 만들어집니다.
이 표를 기억해 두면 다음 덱의 "사후훈련"이 쉽게 이해됩니다 — 사후훈련이란 결국 이 세 단계 중 어디에 다시 손을 대느냐의 문제이기 때문입니다.

📈 숫자 감각 — 14.8조 토큰은 얼마나 큰가

셰익스피어 전집 ≈ 120만 토큰
14.8조 토큰 = 셰익스피어 1,200만 명분
  • 초기 LLM은 단어 단위로 훈련했지만, 현대 LLM은 토큰(짧은 문자열 조각) 단위
  • 덕분에 고유명사처럼 사전에 없는 것도 학습할 수 있다
  • 크기만이 답은 아니다 — 딥시크 팀은 엄격한 중복 제거를 포함한 신중한 데이터 큐레이션이 품질에 기여했다고 밝혔다
💭 데이터의 양보다 선별이라는 메시지는 뒤의 미세조정 절에서 그대로 반복됩니다.
토큰 단위 학습의 실무적 의미: 한국어는 영어보다 토큰을 많이 먹습니다. 같은 문장이라도 비용과 컨텍스트 소모가 달라진다는 뜻입니다.

🧠 전문가 혼합(MoE) — 다 켜지 않는다

총 매개변수
6,710억 개
토큰당 활성
370억 개 (약 5.5%)
  • MoE는 각 토큰에 대해 매개변수 중 일부만 활성화하는 최적화 기법 (DeepSeek-V3 기준)
  • 덕분에 모델은 지시사항 유형마다 다른 경로를 쓸 수 있다
  • 거대한 모델을 거대한 비용 없이 돌리는 방법
💡 "매개변수 수 = 실행 비용"이 더 이상 성립하지 않는다는 뜻입니다. 모델 비교 시 총 파라미터 수만 보면 오해합니다.
MoE는 지도학습 미세조정 단계와 함께 언급되지만, 성격은 아키텍처 최적화입니다. 실무에서는 "이 모델 671B래" 같은 말이 실제 추론 비용과 직결되지 않는다는 점만 챙기면 됩니다.

🔥 DeepSeek-R1의 5단계와 그 안의 돌파구

1콜드 스타트 — 기반 모델(V3-Base)을 수천 개의 다양한 자료점으로 미세조정해 기초를 마련
2순수 강화학습 — SFT 없이 기반 모델에 RL을 직접 적용해 추론 능력 향상 ⭐
3기각 표집 — 성공한 RL 실행에서 가장 좋은 예시를 골라 레이블 데이터를 합성
4SFT — 합성 데이터를 V3-Base의 지도학습 데이터와 병합 (글쓰기 · 사실 QA · 자기 인지)
5최종 RL — 다양한 프롬프트와 시나리오에 걸친 마무리 강화학습
🎯 2단계가 왜 사건인가 — 오랫동안 "추론 능력을 끌어내려면 SFT가 먼저"라고 믿었는데, 순수 RL만으로도 사고 연쇄(CoT) 추론이 창발했습니다(R1-Zero). 사람이 예시를 쓰는 비용이 사라지니 훨씬 다양한 문제로 더 오래 훈련할 수 있게 됐습니다.
덧붙여 R1은 증류(distillation) 버전도 나왔습니다. 이름에 'Distill'이 붙은 것들로, 원천 모델의 추론 능력을 상당 부분 유지하면서 일상적인 하드웨어에서 돌아갑니다. 큐원·라마 아키텍처 기반으로 1.5B/7B/8B/14B 등 여러 크기가 있습니다.

📚 여기까지 한 장으로

1생성형 AI는 프로토타입이 쉽고 프로덕션이 어렵다 — 환각 · 비결정성은 훈련 방식에서 오는 고유 성질
2그래서 설계 패턴이 필요하다. 32개 패턴 = 반복되는 문제에 대한 검증된 해법 + 공통 어휘
3기초 모델 위에 앱을 짓는 일 = AI 엔지니어링. 프롬프트는 지시사항 + 컨텍스트
4호출 방식 셋 — 제공업체 API(통제) · 비종속 프레임워크(이식성) · 로컬(프라이버시)
5모델 제작은 사전훈련 → SFT → RL. 딥시크는 순수 RL만으로 추론 창발을 보였다
6모델은 프런티어 · 증류 · 가중치 공개 · 로컬 네 부류. 고르는 축은 성능 · 비용 · 통제권

✅ 정답 & 해설

A1. 모델을 신뢰하기 어렵기 때문. 환각·비결정성은 생성형 AI 고유의 훈련 방식에서 기인하므로 제거 대상이 아니라 설계로 감싸 다뤄야 할 성질이다.
A2. ① 개발자 간 공통 어휘 확립(의사소통) ② 소프트웨어의 품질·유지보수성·확장성 개선.
A3. 전통 ML은 내 데이터로 모델을 처음부터 훈련. AI 엔지니어링은 범용 데이터로 훈련된 기초 모델 위에 애플리케이션을 짓는다 — 가중치를 못 건드리므로 프롬프트·컨텍스트·오케스트레이션이 주 무기.
A4. 시스템 = 모델의 전반적 동작(역할·원칙), 고정적. 사용자 = 이번 작업의 구체적 지시와 자료, 동적.
A5. SFT 없이 기반 모델에 RL을 직접 적용해 사고 연쇄 추론이 창발함을 보였다. 사람이 예시를 쓰는 비용이 사라져 훨씬 다양한 문제로 더 오래 훈련할 수 있다.
A6. MoE 때문. 토큰당 일부만 활성화되므로(671B 중 37B) 총 파라미터 수 ≠ 실행 비용.
A3을 자기 말로 설명할 수 있으면 이 책 전체의 전제를 잡은 것입니다.
