5.3.1 문제

하나의 경로로는 안 되는 과제
전략적 사고나 논리적 추론을 요구하는 많은 과제는 하나의 다단계 경로를 밀어붙이는 것으로 풀리지 않습니다.

📝 문제 — 네 문장 에세이

무작위 문장 넷이 주어지고, 네 문단으로 된 일관된 글을 쓰되 각 문단이 그 문장 중 하나로 끝나야 한다.

1. To be or not to be, that is the question.        — 셰익스피어
2. Take me to your leader.                          — SF
3. It is a truth universally acknowledged, that a
   single man in possession of a good fortune,
   must be in want of a wife.                       — 오스틴
4. The only thing we have to fear is fear itself.   — 루스벨트
🎓 ToT 논문의 프린스턴·Google DeepMind 연구진은 이것을 창의적 사고와 상위 수준 계획을 둘 다 요구하는 문제로 설명합니다.
⚠️ CoT용 단계별 지시를 구성하기 어렵고, Few-shot CoT가 도움이 될지도 불분명합니다. 그래서 Zero-shot CoT만 남습니다.
패턴 13의 세 변형 중 둘이 적용 불가라는 게 문제 정의의 출발점입니다.

❌ 조건은 맞는데 겉도는 글

Zero-shot CoT의 두 번째 문단

인류 역사 내내 우리는 어려운 선택 앞에서 지침을 구해 왔고 … 고대 문명은 신탁과 주술사에게 물었고, 현대 사회는 멘토·치료사·영적 조언자에게 눈을 돌린다 … Take me to your leader.

각 문단이 지정된 문장으로 끝나긴 했지만 문단들이 말이 잘 안 된다.

이유내용
초기 경로에 갇힌다『햄릿』 인용구가 철학적이라 에세이가 철학적 방향으로 흘러가는데, 이는 다음 두 인용구와 안 맞는다. 초기 경로가 결함이 있으면 해답이 아예 안 나올 수 있다
단 하나의 경로를 따른다초기 경로가 합리적이어도 결과가 최적이 아닐 수 있다. LLM은 종종 특정 사고 흐름에 "갇히고" 되돌아갈 능력이 없다
중간 평가가 없다표준 CoT는 중간 추론 단계의 품질을 평가해서 무엇이 잘 통할지에 근거해 선택할 수 없다
ToT는 응답하기 전에
여러 추론 방향과 대안을 탐색한다
세 이유가 그대로 ToT의 세 기능이 됩니다. 여러 경로 생성, 평가, 백트래킹.

5.3.2 해법

트리 탐색으로 다루기
인간이 어려운 문제에 접근하는 방식과 더 닮았습니다. 대안을 고려하고, 부분적 진전을 평가하고, 문제가 보이면 방향을 바꾸죠.

🧩 네 구성요소

1생각 생성
→
2경로 평가
→
3빔 서치
↶
4요약 생성
구성요소하는 일
생각 생성매 턴마다 LLM이 여러 개의 생각을 만들어 낸다
경로 평가각 경로가 얼마나 유망해 보이는지 점수를 매긴다
빔 서치가장 유망한 상위 K개 경로만 유지한다
요약 생성경로를 소진하면 가장 유망한 경로를 바탕으로 최종 응답을 생성한다
⚠️ 여기서의 빔 서치는 토큰 생성의 빔 서치와 다릅니다. 2장 패턴 1에서 손댔던 그것은 어떤 토큰 시퀀스를 낼지 정하는 것이고, 여기서의 트리와 빔 서치는 더 높은 수준에서 추론 단계로 작동합니다.
같은 이름이라 헷갈리기 쉬워 저자가 따로 박스를 뒀습니다.

① 생각 생성

prompt = f"""{state}
You are solving a problem step-by-step using the Tree of Thoughts method.
Generate {num_thoughts_per_step} distinct and diverse next steps.
This is step {step} of up to {max_steps} steps.
Make each thought meaningfully different to explore diverse approaches."""

thoughts = json.loads(content)   # JSON 리스트로 반환

호출할 때마다 LLM에게 반복의 현재 상태 — 지금의 상위 K개 해법 — 을 제시한다.

에세이 문제 · 1단계에서 생성된 생각 셋

1. 인용구 다수가 선택과 관련되니 의사결정이라는 주제로 구성할 수 있겠다
2. 창의적 서사를 만들 수 있겠다 — 아마도 외계인과의 조우가 철학적 성찰로 이어지는 이야기
3. 먼저 각 인용구의 주제를 식별한 다음(실존적 물음 · 외계 접촉 · 사회적 기대 · 두려움 극복) 응집력 있는 에세이를 짓겠다

💡 첫째는 공통점 찾기, 둘째는 영감 어린 서사, 셋째는 전략적 접근. 셋 다 통할 만한데 어느 것이 최선이고 먼저 탐색해야 할까?
"meaningfully different"라는 지시가 중요합니다. 비슷한 생각 셋을 만들면 트리를 만드는 의미가 없어요.

② 경로 평가 — 0~100점

prompt = f"""Problem: {problem}
Reasoning path: {state}

On a scale from 0 to 100, evaluate how promising this path is.
Consider:
1. Correctness - Is the reasoning logically sound?
2. Progress - How much progress toward the solution?
3. Insight - Does it show understanding of key aspects?
4. Potential - How likely to lead to a complete solution?

Respond with a single integer. Only the number, nothing else."""

score = int(content) / 100.0   # 0~1 스케일로
1단계 후 상위 3개 상태
점수경로
0.75먼저 각 인용구의 주제를 식별하겠다
0.60창의적 서사를 잇겠다 (외계인 조우)
0.60각 문단이 주어진 문장으로 끝나는 에세이를…
✅ 가장 유망한 접근은 먼저 각 인용구의 주제를 식별하는 것임을 알려 줍니다.
네 가지 평가 기준이 명시적인 게 핵심입니다. "좋아 보이나?"만 물으면 점수가 의미 없어져요.

③ 트리 탐색 — 음수 점수 트릭

thoughts = self.generate_thoughts(current_state, step)
for thought in thoughts:
    new_state = f"{current_state}\nStep {step}: {thought}"
    new_score = self.evaluate_state(new_state, problem)
    candidates.append((-new_score, new_state, new_path, step))
                       # 가장 작은 값 = 최선이 되도록

beam = []
for candidate in heapq.nsmallest(self.beam_width, candidates):
    score, state, path, s = candidate
    beam.append((-score, state, path, s))
💡 이 개념이 빔 서치에만 국한되지 않습니다. 너비 우선 탐색이나 깊이 우선 탐색 같은 다른 방법도 쓸 수 있습니다.
# 조기 종료 — 훌륭한 해법을 만나면
if new_score > 0.9:
    best_final_states.append((new_score, new_state, new_path))
💡 평가 점수가 높은 해법을 만나면 트리 탐색을 조기 종료하거나, n단계 후 최선의 제안을 고를 수 있습니다.
heapq는 최소 힙이라 최댓값을 뽑으려면 부호를 뒤집는 게 관용적인 방법입니다.

④ 요약 생성 — 그리고 결과

선택된 추론 경로

1단계: 창의적 서사 — 외계인과의 조우가 철학적 성찰로
2단계: 인류의 탐험에 관한 에세이 — 목적에 대한 물음 / 외계 생명 / 인간의 연결 / 두려움 넘기
3단계: 이것을 문학 자체에 관한 에세이로 틀 잡을 수 있겠다 — 셰익스피어의 실존적 물음, SF의 미지 탐구, 오스틴의 사회 비평, 루스벨트의 용기
4단계: 문학을 통해 본 인간 본성에 관한 에세이를 쓰겠다

생성된 에세이 (첫 문단)

# 문학의 지속되는 힘
인류 역사 내내 문학은 존재와 목적에 대한 우리의 가장 깊은 물음을 비추는 거울이었다 … 셰익스피어 같은 작가들은 실존적 딜레마를 비할 데 없는 웅변으로 포착해 … To be or not to be, that is the question.

훨씬 낫다 — 약간의 계획과 평가가 큰 차이를 만든다
💡 1단계에서 0.60점이던 "외계인 조우"가 살아남아 3단계에서 "문학에 관한 에세이"로 진화한 것에 주목하세요 — 초기 최고점이 최종 승자가 아닙니다.
이게 트리 탐색의 진짜 가치입니다. 1등만 밀고 갔으면 이 경로는 사라졌을 거예요.

5.3.3 예제

공급망 최적화
해법이 여럿 있는 현실적인 전략 문제입니다. ToT는 전략적 문제에서 강한 결과를 보여 왔어요.

🚚 문제 — 공급망 구성

현재 상황
- 제조 후보지 3곳 (멕시코, 베트남, 폴란드)
- 물류센터 4곳 (애틀랜타, 시카고, 댈러스, 시애틀)
- 주요 운송 수단 2가지 (항공, 해상)
- 과거 수요 변동 ±20%
- 최근 아시아 해운 항로의 교란
요청
1서로 다른 공급망 구성 3가지를 생성
2각 구성에 대해 3가지 시나리오 성능 탐색 — 정상 운영 / 대규모 해운 교란 / 수요 30% 증가
3총비용 · 배송 시간 신뢰성 · 교란 취약성으로 평가
4각 경로의 리스크 조정 성능 비교
5비용 · 속도 · 복원력의 균형이 가장 좋은 구성 식별
CoT로는 이 다섯 요구를 동시에 다루기 어렵습니다. 구성마다 시나리오가 셋이니 조합이 아홉이에요.

🌲 탐색 과정

1단계 생각 셋 → 채점
점수생각
0.65운송 네트워크를 매핑하고 항공·해상 기준 비용과 시간을 계산해 병목과 취약점을 식별
0.35각 제조 후보지의 핵심 속성을 정의해 비교 기준선을
0.35가장 유망한 제조-물류 짝을 먼저 식별한 뒤 구성 셋을
2단계 — 각 노드마다 다시 생각 셋 (첫 노드에서)
점수생각
0.75구성 A 비용 최소화(멕시코+느린 운송) / B 속도(균형+항공) / C 복원력(전 지역 분산 제조)
0.75각 입지의 고유 특성(인건비 · 시장 근접성 · 정치적 안정성 · 인프라)을 먼저 분석
0.65정량 채점 매트릭스를 만들어 세 시나리오를 평가
💡 2단계에서 점수가 0.65 → 0.75로 올라갑니다. 경로가 구체화되면서 유망해지는 것이 점수로 보입니다.
둘째 노드에서도 생각 셋이 나오고, 셋째에서도 나옵니다. 매 층마다 후보가 아홉 개씩 생기는 거죠.

🎉 최종 해법과 비용

선택된 추론 경로 (4단계)

1 운송 네트워크 매핑 → 2 구성 A/B/C 생성 → 3 세 시나리오 아래 성능 매트릭스 → 4 각 시나리오의 확률을 변화시키며 민감도 분석

✅ 해법 요약

최적은 구성 C — 멕시코·폴란드·베트남 분산 제조 + 운송 수단 혼합.
• A(비용 우선)는 정상 조건에선 좋았지만 교란 시 심각하게 무너졌다
• B(속도 우선)는 신뢰성은 좋았지만 비용이 크게 높았다
• C는 모든 시나리오에서 균형이 가장 좋았다 — 내재된 이중화로 교란과 수요 변동에 빠르게 적응

모델 API 호출41회
전체 소요 시간93초 — 실제 애플리케이션에서는 상당한 시간

⚠️ 5.3.4 복잡도

표준 프롬프팅이나 CoT로 충분한 단순 과제에서
ToT는 이득이 거의 없다
오버헤드내용
조합 폭발빔 폭 · 탐색 깊이 · 반복당 생각 수의 균형을 찾는 것 자체가 복잡도를 키운다. 어떤 문제는 탐색 공간이 지수적으로 커져 탐색이 비현실적이 된다
높은 지연과 비용생각을 만들고 점수를 매기려면 요청을 여러 번 보내야 한다. 트리의 폭과 깊이에 따라 몇 분이 걸릴 수 있는데, 이는 현실 LLM 애플리케이션의 지연 한계를 넘어선다
복잡성생각 생성 · 채점 · 빔 서치 · 요약 생성이 다 필요하고 상태 · 탐색된 경로 · 단계 수를 추적해야 한다. 트리 탐색 구현 각각이 그 자체로 작은 프로젝트이고, 복잡도가 늘면 구현 버그의 여지도 커진다
💡 그래서 CoT부터 시작하라는 것입니다. 41회 호출과 93초는 사용자가 기다릴 수 있는 시간이 아닌 경우가 많습니다.
파라미터 튜닝이 곧 복잡도라는 지적이 정확합니다. 빔 폭 하나 정하는 것도 실험이 필요해요.

🔁 대안 — 추론 모델과 LtM

🧠 추론 모델

ToT가 처음 구상된 이후 LLM은 진화해 훨씬 나은 추론 능력을 갖게 됐다. 복잡성을 감당하는 대신 OpenAI o3 · Anthropic Opus · Gemini 2.5 Pro · DeepSeek-R1 같은 강한 추론 모델을 쓰는 것이 좋은 대안이다.

현대 LLM의 사고 모드는 외부 트리 아키텍처의 오버헤드 없이 추론을 끌어올린다. 이런 능력은 어텐션 메커니즘이나 추가 처리 층을 통해 아키텍처 수준에 통합될 수 있어, 프로덕션 배포에 더 효율적이고 비용 효과적이다.

📏 최소-최대 프롬프팅 (LtM)

문제를 더 단순한 순차적 하위 문제로 분해한 뒤 (CoT처럼) 각 단계를 순서대로 푼다.

언제 — 이전 단계가 이후 단계의 해법을 알려 주는 순차적 분해가 자연스러운 문제(다단계 수학, 프로그래밍, 추론 사슬).

결합도 가능 — LtM으로 쪼갠 뒤, 특히 복잡한 하위 문제에만 ToT를 적용.

추론 모델이 나오면서 ToT를 직접 구현할 이유가 많이 줄었습니다. 그래도 개념은 알아야 사고 모드가 뭘 하는지 이해하죠.

🔁 대안 — 리플렉션과 wait 주입

🔍 리플렉션

LLM이 자기 출력을 평가하고 비판하게 하는 에이전트 기법. 자기 생성물을 "되돌아보고" 기대에 못 미치면 폐기할 수도 있다.

다만 리플렉션도 문제를 선형적으로 다룬다. → 6장 패턴 18

⏳ wait 주입 (예산 강제, budget forcing)

기발한 만큼 단순하다 — 모델이 출력을 끝내려 할 때 Wait라는 낱말을 끼워 넣는다. 생성 중에 종료 토큰을 Wait로 덮어쓴다.

시퀀스 종료 토큰이 사라지면 모델은 생성을 계속하게 되고, 결과적으로 앞선 진술을 재평가하게 된다. 최종 응답은 처음보다 훨씬 성찰적인 경우가 많다.

📑 2장 패턴 1 로짓 마스킹과 같은 자리에서 개입합니다 — 종료 토큰을 막아 생성을 이어 가게 하는 것.
wait 주입이 이 장에서 가장 저렴한 대안입니다. 구현이 몇 줄이면 되니까요.
