## 1.1 왜 설계 패턴인가

### 문제 정의

| | |
|---|---|
| **쉬운 것** | 생성형 AI는 강력하고 쓰기 쉬워, 비전문가도 인상적인 프로토타입을 만든다 |
| **어려운 것** | 그 프로토타입을 **프로덕션 수준**으로 끌어올리는 일 |
| **이유** | 모델을 **신뢰하기 어렵다** — 환각, 같은 입력에 다른 답(비결정성) |

핵심은 이것이 **버그가 아니라는 점**이다. 대부분 생성형 AI 모델의 **고유한 훈련 방식에서 기인**하므로 피하기 어렵다. 제거 대상이 아니라 **설계로 감싸 다뤄야 할 성질**이다.

### 설계 패턴이란

소프트웨어를 만들며 반복해서 만나는 공통 문제에 대한 **검증된 해법**. 오랜 집단 경험으로 다듬어진 표준 모범관행.

**두 가지 이득**
1. 개발자 간 **공통 어휘**를 확립한다 (의사소통)
2. 소프트웨어의 **품질 · 유지보수성 · 확장성**을 개선한다

**계보**

```
1977 건축(알렉산더 『A Pattern Language』)
  → 1994 GoF 『Design Patterns』(객체지향)
  → 자바 EE · 머신러닝 등 분야별 확장
  → 지금: 생성형 AI (이 책, 32패턴)
```

### 용어 네 개

| 용어 | 뜻 |
|---|---|
| **기초 모델** (foundation model) | 대규모 범용 데이터셋으로 미리 훈련된 모델. GPT-4, 제미나이, 클로드, 라마, 딥시크, 큐원, 미스트랄 |
| **AI 엔지니어링** | 모델을 처음부터 훈련하지 않고 **기초 모델 위에** 애플리케이션을 짓는 접근법 (칩 후옌 『AI Engineering』 용어) |
| **프롬프트** | 기초 모델에 주는 텍스트 입력 |
| **에이전트** | 기초 모델의 도움으로 **작은 문제 하나**를 해결하는 소프트웨어 구성 요소 |

> 🔄 **발상의 전환** — 전통 ML은 "내 데이터로 내 모델을 훈련"했지만, AI 엔지니어링은 "남이 훈련한 범용 모델을 내 문제에 맞게 다루는" 일이다. 가중치를 못 건드리니 **프롬프트·컨텍스트·오케스트레이션**이 주 무기가 되고, 그래서 패턴이 필요해진다.

### 프롬프트 한 번으로 안 되는 것들

| 문제 | 다루는 장 |
|---|---|
| 원하는 스타일과 다르다 | 2장 |
| 기업 내부 지식이 반영되지 않는다 | 3·4장 |
| 특정 역량 자체가 부족하다 | 5장 |
| 한 번 호출로 감당 안 되는 복잡한 작업 | 작게 쪼개 **에이전트**로 |

**각 패턴 절의 고정 구조**: 문제 → 검증된 해법 → 구체적 예시 → 대안·고려사항

## 1.2 기초 모델에 기반한 애플리케이션 구축

### 프롬프트 = 지시사항 + 컨텍스트

- **지시사항(instruction)** — 모델이 수행할 작업. 가장 단순한 프롬프트는 이것뿐
- **컨텍스트(context)** — 맥락 정보. 생성 시 활용할 자료이거나, 모델에게 맡기는 역할·성격

프롬프트도 응답도 **다중 모달**일 수 있다 (텍스트 · 이미지 · 비디오 · 오디오).

### 호출하는 세 가지 길

**① 제공업체 API 직접**

```python
import anthropic
client = anthropic.Anthropic()   # 생략 시 ANTHROPIC_API_KEY 환경변수 사용

completion = client.messages.create(
    model="claude-sonnet-4-5",
    system="당신은 파이썬 프로그래밍 전문가입니다.",        # 시스템 프롬프트
    messages=[{
        "role": "user",
        "content": [{"type": "text",
                     "text": "주어진 정수 목록의 중앙값을 구하는 코드를 작성하세요."}]
    }]                                                    # 사용자 프롬프트
)
print(completion.content[0].text)
```

| 구분 | 역할 | 성격 |
|---|---|---|
| **시스템 프롬프트** | 모델의 전반적인 동작 안내 (역할·톤·원칙) | 상대적으로 **고정적** |
| **사용자 프롬프트** | 이번에 수행할 구체적 지시와 자료 | 매 요청 **동적** |

**② LLM 비종속 프레임워크** — 이식성

```python
from pydantic_ai import Agent

agent = Agent('anthropic:claude-sonnet-4-5',
              system_prompt="당신은 파이썬 프로그래밍 전문가입니다.")
result = agent.run_sync("주어진 정수 목록의 중앙값을 구하는 코드를 작성하세요.")
print(result.data)
```

제공업체 교체 = **모델 식별 문자열만 교체**
`'openai:gpt-4o-mini'` · `'google-vertex:gemini-2.0-flash'` · `'groq:llama3-70b-8192'`

> 클래스 이름이 `Agent`라는 점에 주목. 프레임워크는 이미 모델 호출을 "에이전트"로 부른다.

**③ 로컬 실행 (올라마)** — 프라이버시 · 비용 0

```python
from pydantic_ai.models.openai import OpenAIModel
from pydantic_ai.providers.openai import OpenAIProvider

model = OpenAIModel(
    model_name='llama3.2',
    provider=OpenAIProvider(base_url='http://localhost:11434/v1')
)
```

얻는 것: 데이터가 로컬을 벗어나지 않음, API 비용 없음
잃는 것: 클라우드 모델보다 **기능이 현저히 떨어짐**

### 기초 모델은 어떻게 만들어지나 (딥시크 공개 정보 기준)

```
① 사전훈련 → ② 지도학습 미세조정(SFT) → ③ 강화학습(RLHF)
```

| 단계 | 얻는 능력 | 재료 |
|---|---|---|
| **① 사전훈련** | 일반적 언어 이해 — 앞 토큰들로 다음 토큰 예측 | 말뭉치 **14.8조 토큰** |
| **② SFT** | 지시를 따르는 능력 — 전문가가 쓴 이상적 응답 모방 | 사람이 쓴 선별된 예시 |
| **③ RLHF** | 인간의 기대·가치에 정렬 (= 선호도 조정/최적화) | 결과물 쌍의 선호 판정 |

LLM을 "다음 토큰 예측기"라 부르지만 그건 **1단계일 뿐**이다. 우리가 쓰는 모델의 성격은 2·3단계에서 만들어진다.

**숫자 감각** — 셰익스피어 전집 ≈ 120만 토큰 → 14.8조 토큰 = **셰익스피어 1,200만 명**분.
단, 크기만이 답은 아니다. 딥시크 팀은 **엄격한 중복 제거를 포함한 신중한 데이터 큐레이션**이 품질에 기여했다고 밝혔다.

**전문가 혼합(MoE)** — 각 토큰에 대해 매개변수 중 일부만 활성화.
DeepSeek-V3는 총 **6,710억** 개 중 토큰당 약 **370억** 개(≈5.5%)만 활성.
→ ⚠️ **총 파라미터 수 ≠ 실행 비용.** 모델 비교 시 파라미터 수만 보면 오해한다.

**DeepSeek-R1의 5단계**

1. **콜드 스타트** — 기반 모델(V3-Base)을 수천 개의 다양한 자료점으로 미세조정
2. **순수 강화학습** — SFT 없이 RL을 직접 적용해 추론 능력 향상 ⭐
3. **기각 표집** — 성공한 RL 실행에서 좋은 예시를 골라 레이블 데이터 합성
4. **SFT** — 합성 데이터를 V3-Base의 지도학습 데이터와 병합 (글쓰기·사실 QA·자기 인지)
5. **최종 RL** — 다양한 프롬프트·시나리오에 걸친 마무리

> **2단계가 왜 사건인가** — 오랫동안 "추론을 끌어내려면 SFT가 먼저"라고 믿었는데, 순수 RL만으로 **사고 연쇄(CoT) 추론이 창발**했다(R1-Zero). 사람이 예시를 쓰는 비용이 사라지니 훨씬 다양한 문제로 더 오래 훈련할 수 있게 됐다.

**증류(distillation)** — 이름에 'Distill'이 붙은 버전들. 원천 모델의 추론 능력을 상당 부분 유지하면서 일상적 하드웨어에서 실행. 큐원·라마 아키텍처 기반 1.5B/7B/8B/14B 등.

### 모델 지형도

**평가** — 학술 벤치마크는 **포화 상태이고 조작 가능성**도 크다. 현재 가장 널리 인정받는 방식은 **블라인드 쌍 비교**이며 대표 프로젝트가 **LMArena**.

리더보드 읽는 법: y축 = 엘로 점수, x축 = 비용, **둘 다 로그 축척**.
x축 기준 → 예산에 맞는 최고 모델 / y축 기준 → 이 성능의 최저 가격.

**네 부류**

| 부류 | 예 | 특징 | 언제 |
|---|---|---|---|
| **프런티어** | GPT-5, 제미나이 2.5 프로, 클로드 | SOTA. 추론·지식·다중모달 최고, 컨텍스트 최대 200만 토큰. 비싸고 무겁고 독점적이라 로컬 불가 | 정교한 추론 필요, 속도 안 급한 엔터프라이즈 |
| **증류** | 제미나이 플래시, 클로드 소네트, GPT 미니 | 성능·효율 균형. 싸고 빠름 (플래시는 프로보다 **20배 저렴**) | 콘텐츠 생성·요약 등 고용량 작업 |
| **가중치 공개** | 라마, 미스트랄, 딥시크, 큐원, 팰컨 | 투명성·자체 최적화·독점 데이터 미세조정 가능. 성능은 대개 프런티어에 못 미치고 호스팅에 전문 지식 필요 | 커스텀·소유가 필요할 때 |
| **로컬** | 라마 8B, 젬마 2B | 완벽한 프라이버시, API 비용 0. 기능은 현저히 낮음 | 데이터 반출 금지·오프라인 |

**에어 갭** — 인터넷 단절 환경에서도 프런티어 모델을 쓰려는 수요에 대응해, 구글은 **Google Distributed Cloud**로 제미나이를, 오픈AI는 **MS 애저 온프레미스**로 GPT를 온프레미스 실행할 수 있게 했다. "프라이버시가 필요하면 작은 로컬 모델뿐"이라는 이분법이 깨지는 중.

## 1.3 에이전트형 AI

### 에이전트란

컴퓨터 과학에서 **사용자나 다른 프로그램을 대신해 행동하는 소프트웨어 개체**. 모델에 역할을 주고, 맥락을 주고, 지시를 수행하게 하는 순간 그 LLM은 이미 나의 대리인이다.

```python
agent = Agent(
    f"anthropic:{MODEL_ID}",
    system_prompt="당신은 재고 관리자입니다. 물품을 적시에 주문해야 합니다.",
)
```

**"어떻게" 관리하라는 말이 한 줄도 없다.** 목표만 주었다.

```python
@dataclass
class InventoryItem:
    name: str
    quantity_on_hand: int
    weekly_quantity_sold_past_n_weeks: list[int]
    weeks_to_deliver: int

items = [
    InventoryItem("itemA", 300, [50, 70, 80, 100], 2),
    InventoryItem("itemB", 100, [70, 80, 90, 70], 2),
    InventoryItem("itemC", 200, [80, 70, 90, 80], 1),
]

result = agent.run_sync(f"다음 품목 중 이번 주에 다시 주문해야 하는 것들을 파악하세요.\n{items}")
```

> 사람이 계속 안내하거나 명시적으로 프로그래밍하지 않아도 독립적으로 작동하는 **자율성** — 이것이 전통 소프트웨어와 AI 에이전트를 가르는 **핵심 차별점**이다.

### 에이전트에 기대하는 네 가지

| 특징 | 뜻 | 재고 관리자 예 | 이어지는 패턴 |
|---|---|---|---|
| **목표 지향성** | 프롬프트에 반응하는 게 아니라 목표를 향해 작동 | "적시에 주문한다"를 시스템 프롬프트로 | — |
| **계획 및 추론** | 목표 달성 단계를 스스로 계획 | 판매량 범위 → 배송기간 고려 → 최대 수요 예측 → 수량 계산 | 사고 연쇄(13), 사고 트리(14) |
| **인지 및 행동** | 데이터를 수집(인지)하고 환경에 행동 — 외부 함수 호출 | DB에서 재고 직접 조회, API로 **주문까지 실행** | **도구 호출(21)** |
| **적응 및 학습** | 자기 출력을 평가하고 스스로 수정 | "300개가 정말 맞나" 재검증 | 성찰(18), 자체점검(31) |

### 그런데 아직 목표일 뿐이다

> 에이전트형 행동 방식은 기초 모델 기반 애플리케이션이 **지향하는 목표일 뿐, 완전히 실현되지는 못했다.**

- **비결정성** — 매번 재주문 목록과 수량이 다르게 나올 수 있다
- **환각** 등 여러 실패 모드
- 간단한 문제엔 계획을 잘 세우지만 **복잡해지면 무너진다**

이 책의 패턴들은 애플리케이션을 "더 에이전트답게 만들거나, **최소한 구축 가능한 것의 범위를 넓히는**" 방법이다.

## 1.4 레버 ① 세밀한 제어

> 초매개변수의 수학적 토대를 이해하면 **뒤의 설계 패턴을 쓰는 것보다도 더 간단하고 효과적으로** 모델을 제어할 수 있다.

### 로짓과 소프트맥스

언어 모델은 수백 개 층이지만 **다음 토큰을 예측하는 건 마지막 층 하나**다. 토큰 하나가 아니라 **후보 집합 전체와 각 후보의 확률**을 함께 내놓는다. 마지막 층 출력이 **로짓(logit)** — 정규화되지 않은 원시 수치.

```
P(token_i) = exp(logit_i) / Σ_j exp(logit_j)
```

소프트맥스는 **높은 값(peak)은 부각하고 낮은 값(tail)은 억제**한다. 분포가 원래 덜 뾰족하면 그 효과도 덜하다.

**탐욕 표집(greedy)** — 항상 로짓이 가장 큰 토큰만 선택. 매우 **반복적이고 재미없는** 텍스트가 나오기 쉽다. 그래서 언어 모델은 **어떤 후속 단어라도 확률이 0이 되지 않는** 표집 전략을 쓴다.

### 온도 (T)

```
P(token_i) = exp(logit_i / T) / Σ_j exp(logit_j / T)
```

소프트맥스 적용 **전에** 로짓 크기를 조절한다.

| T | 효과 | `The trade war caused...` 실측 |
|---|---|---|
| 0.0 | 사실상 탐욕 표집 | 공급망 혼란·가격 상승 — **한 문장** |
| 0.5 | 균형 | 제조업체·농가·장기 효과까지 **3문장** |
| 0.8 | 꼬리 단어 확률↑ → 더 창의적 | 기업 이익·금융시장 변동성·**외교 관계**까지 |

단, 애초에 분포가 덜 뾰족했다면 온도를 올려도 변화가 덜 두드러진다.
**RAG(3장)·심판형 LLM(6장)에서는 온도를 낮게 또는 0으로** 둔다.

```python
# 파이댄틱 AI
agent = Agent('anthropic:claude-sonnet-4-5',
              model_settings={"temperature": 0.5},
              system_prompt="문장을 완성하세요.")

# 앤트로픽 API 직접
completion = client.messages.create(
    model="claude-sonnet-4-5",
    system="문장을 완성하세요.",
    temperature=0.5,
    messages=[ ... ]
)
```

> **초매개변수**라 부르는 이유 — 모델의 **매개변수**(신경망 가중치)와 구분하기 위해. 가중치는 못 건드려도 이건 매 호출마다 바꿀 수 있다.

### 상위 K 표집 (Top-K)

가장 가능성 높은 토큰 **k개**로만 선택을 제한 → 확률 분포의 **긴 꼬리를 잘라낸다.**

| K | `The spaceship...` 결과의 성격 |
|---|---|
| 1 | "zoomed through the vast expanse..." — 기존 SF 상투구에 가장 가까움 |
| 10 | "glided silently through the vast emptiness..." |
| 100 | "soared through the starry expanse, gleaming hull reflecting alien suns..." — 가장 풍부 |

온도와 함께 쓰는 이유: **온도가 높을 때 엉뚱한 단어가 튀는 것을 K가 막아준다.**

### 상위 P 표집 (Top-P, 중핵 표집)

**누적 확률이 임곗값 p를 넘는 최소 집합**을 동적으로 선택. 확률 질량 대부분을 차지하는 토큰들의 **중핵(nucleus)**.

- 모델이 **확신할 때** → 적은 수의 토큰만 고려 (K 낮은 Top-K와 비슷)
- 모델이 **헷갈릴 때** → 더 많은 토큰 고려 (K 높은 Top-K와 비슷)

> **Top-K는 "몇 개"를 고정하고, Top-P는 "얼마만큼의 확률"을 고정한다.**

### 빔 탐색

모델은 후속 토큰을 한 번에 하나씩만 고르지 않는다. **결정론적 탐색 알고리즘**으로 여러 시퀀스를 병렬 탐색해 **확률이 가장 높은 시퀀스**를 찾는다 → 다음 토큰이 아니라 **전체 시퀀스의 확률**을 고려.

**반복 벌점**
- **빈도 벌점** — 반복 횟수에 비례해 벌점 증가
- **출현 벌점** — 한 번이라도 반복되면 동일 벌점 → 더 다양한 토큰 유도

**길이 벌점**
- **최소 길이** — 최소 토큰 수 강제
- **최대 길이** — 넘기면 생성 종료
- **길이 정규화** — 시퀀스 점수를 길이의 함수로 나눠 짧은 시퀀스 선호 편향 방지

**빔 너비** — 생성 중 고려하는 병렬 시퀀스 개수

> ⚠️ **지원 현황 주의** — 집필 시점 기준 오픈AI·구글은 반복 벌점을 지원하지만 **앤트로픽은 지원하지 않는다.** 허깅페이스 Transformers는 길이 벌점과 빔 너비 변경을 지원하지만, **허깅페이스에 호스팅된 모델 중 이를 지원하는 것은 없다.**

## 1.5 레버 ② 컨텍스트 내 학습

| 전통 ML | LLM |
|---|---|
| 새 작업 = **재훈련** (가중치 변경) | 새 작업 = **프롬프트 변경** (가중치 그대로) |

**컨텍스트 내 학습(in-context learning)** — 기초 모델이 프롬프트에 주어진 예시나 지시사항만으로 새 작업에 적응하는 능력. 다양한 작업 형식과 지시사항이 섞인 데이터셋으로 훈련된 덕분에 생긴 능력이다.

- **제로샷** — 예시 없이 작업만 지시. 사전훈련 지식 + 자연어 이해력에 의존
- **퓨샷** — 예시 몇 개를 추가. 작업의 구조와 **출력 형식**을 시연(demonstration)

> 중요: **모델의 가중치는 전혀 변경되지 않는다.** 이미 지닌 지식을 활용해 새 작업을 수행할 뿐이다. 그 요청 안에서만 유효하며 다음 요청에 남지 않는다.

```python
agent = Agent(MODEL_ID, system_prompt="""당신은 미술사 전문가입니다.
사용자가 어떤 그림을 설명하면 무슨 그림인지 알아내야 합니다.""")

result = agent.run_sync("""
Example:
설명: 전경에 작은 조각배 두 척과 붉은 태양이 보인다.
답변:
  그림: 인상, 해돋이
  화가: 클로드 모네
  연도: 1872
  의의: 인상주의 운동에 이름을 붙여 준 작품...

설명: 야외 텐트 아래 테이블에서 한 무리의 사람들이 식사를 한다.
      남자들은 보팅 햇(boating hat)을 쓰고 있다.
""")
```

→ 모델은 설명과 일치하는 **르누아르의 그림**을 정확히 짚었다. 도메인 특화 모델을 만들지도, 훈련 데이터를 모으지도 않고.

예시 하나가 한 일: ① 무슨 **형식**으로 답할지 ② 어느 정도 **깊이**로 답할지. 퓨샷은 "정답을 가르치는 것"이 아니라 **"형식과 태도를 보여주는 것"**에 가깝다.

### 컨텍스트 엔지니어링과 한계

**컨텍스트 엔지니어링** = 잘 다듬은 데이터와 지시사항을 프롬프트의 컨텍스트에 넣어 모델이 원하는 방식으로 작동하게 만드는 일. 퓨샷 학습은 그 가장 간단하고 효과적인 형태.

**강점** — 방대한 데이터셋 선별 불필요 / 프로토타이핑이 빠름 / 프로덕션에서도 **예시 갱신이 재훈련·재배포보다 훨씬 빠름**

**한계 네 가지**
1. 기초 모델이 **이미 필요한 지식과 역량을 갖춘 경우에만** 작동
2. 예시가 많아지면 **컨텍스트 창의 토큰을 소모**하고 실행이 **느려진다**
3. 소수 예시로는 **복잡한 문제 일반화가 어렵다**
4. 그럴 땐 **사후훈련**이 나은 접근

## 1.6 레버 ③ 사후훈련

사전훈련된 모델의 **가중치를 수정**해 새 작업·도메인에 맞추는 방법들의 총칭. 훈련 후 **재배포**해야 하고, 종단점도 기초 모델과 달라진다.

### 네 가지 방법

| 방법 | 내용 | 주의 |
|---|---|---|
| **CPT** (후속 사전훈련) | 기존 훈련에 없던 어휘·연관 관계를 추가 학습. 기반 모델의 **가중치 전체와 아키텍처 접근** 필요 | 비용·시간 막대. **한 단계를 다시 하면 나머지 단계도 다시** 해야 함. 블룸버그 사례 이후 **선택하는 조직이 거의 없다** |
| **SFT** (지도학습 미세조정) | (프롬프트, 응답) 쌍으로 추가 훈련. 다양한 지시로 훈련하면 제로샷 능력 강화 = **지시사항 조정** | **한 가지 작업만** SFT하면 이전 작업을 잊고 일반화도 실패 |
| **PeFT** (LoRA·QLoRA) | 원천 가중치는 **동결**, 작은 **어댑터 행렬**만 훈련. 훈련 매개변수 **최대 1/10,000**, GPU 메모리 **최대 1/3** | 지연시간 증가 없이 전체 미세조정에 가까운 성능. QLoRA는 양자화 → 훈련은 느리지만 메모리 효율↑, 실행은 더 빠름 |
| **선호도 조정** | 같은 프롬프트에 두 결과를 만들고 어느 쪽이 나은지 피드백. 사람 + RL = **RLHF** | 효율 때문에 **DPO**를 많이 씀. 딥시크는 **GRPO**(그룹 평균 보상 정규화)로 좋은 결과 |

> **블룸버그 사례** — 2023년 3월 금융 문서로 CPT를 했는데, 불과 몇 달 뒤 **범용 기초 모델이 그 도메인 특화 모델을 가뿐히 능가**했다. 기초 모델의 발전 속도가 도메인 특화의 이점을 삼켜버린 것.

### 데이터셋의 모양이 방법을 정한다

| 내가 가진 데이터 | 쓸 수 있는 방법 |
|---|---|
| 순수한 **텍스트 완성** 항목뿐 | **CPT** (비지도) — 새 어휘·새 연관 관계 |
| **입력-출력 쌍** (이상적 응답) | **SFT · 지시사항 조정** |
| 입력 + **두 응답** + **선호 표시** | **선호도 조정** (RLHF·DPO·GRPO) |

이 셋 **모두** PeFT 방식으로 수행하거나 양자화 모델에 적용할 수 있다. PeFT는 별개 선택지가 아니라 **위에 겹쳐 쓰는 방식**이다.

> ⚠️ 집필 시점(2025-06) 기준 **모든 형태의 사후훈련을 지원하는 것은 가중치 공개 모델뿐.** 호스팅 모델은 제공업체 문서에서 지원 여부를 확인해야 한다.

### 코드

**프런티어 모델** — JSONL 업로드 후 작업 생성 (최소 100쌍, 수천 쌍이면 더 좋음)

```python
training_file = client.files.create(file=open("training_data.jsonl", "rb"),
                                    purpose="fine-tune")
job = client.fine_tuning.jobs.create(training_file=training_file.id,
                                     model="gpt-3.5-turbo")

job_status = client.fine_tuning.jobs.retrieve(job.id)
if job_status.status == 'succeeded':
    print(f"Model ID: {job_status.fine_tuned_model}")
# ft:<BASE_MODEL>-0125:<ORG_NAME>::<JOB_ID> 형식
# 이후 model 필드만 바꿔 평소처럼 호출
```

**가중치 공개 모델** — 언슬로스 + LoRA

```python
from unsloth import FastLanguageModel

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="unsloth/Meta-Llama-3.1-8B-bnb-4bit",
    max_seq_length=2048, load_in_4bit=True, dtype=None)

model = FastLanguageModel.get_peft_model(model, r=16,
    target_modules=["q_proj","k_proj","v_proj","up_proj",
                    "down_proj","o_proj","gate_proj"],
    use_gradient_checkpointing="unsloth")

SFTTrainer(model=model, tokenizer=tokenizer,
           train_dataset=dataset, dataset_text_field="text").train()

model.save_pretrained_merged("model", tokenizer, save_method="merged_16bit")
```

`r=16`은 LoRA 계층의 계수(행렬 차원), `target_modules`는 어댑터를 붙일 위치 — 주의 메커니즘 행렬(Q,K,V)과 여러 사영 계층.

### 미세조정의 진짜 비용 네 가지

| 항목 | 내용과 완화책 |
|---|---|
| **데이터 요구사항** | 컨텍스트 내 학습은 예시 몇 개면 되지만 미세조정은 **100개 이상**. → 일단 컨텍스트 내 학습으로 시작해 **데이터를 모으고** 나중에 미세조정 |
| **파국적 망각** | 미세조정 예시를 과대평가해 **기존 지식을 잃는** 현상. LLM 최대 장점인 **포괄적 세상 지식**을 무력화. → 작은 데이터셋으로 **몇 에포크만** 먼저, 학습률은 사전훈련 종료 시점 값(**1e-5 부근**)에서 시작 |
| **추가적 복잡성** | 배포 전 **성능 평가**(편향된 언어 등 역효과 확인) · 기초 모델 **새 버전마다 재조정** · 훈련/검증 데이터 **계보 추적** |
| **추가 비용** | 제공업체는 미세조정 모델에 **토큰당 더 높은 요금**. 가중치 공개는 실행비는 줄지만 **훈련 GPU 비용** — 몇 달러에서 **버전별 수백 달러**까지 |

> 저자들의 결론 — **"미세조정으로 얻는 이득이 이 골칫거리들을 능가하는지 미리 확인하라."**

1. 생성형 AI 프로토타입을 프로덕션으로 올리기 어려운 **근본 이유**는? 그것이 "버그"가 아닌 이유는?
2. 설계 패턴이 주는 이득 **두 가지**는? (하나는 코드가 아니라 사람에 관한 것)
3. 전통적 ML과 **AI 엔지니어링**의 결정적 차이는?
4. 시스템 프롬프트와 사용자 프롬프트는 각각 무엇을 담고 성격이 어떻게 다른가?
5. DeepSeek-R1의 **순수 강화학습**이 왜 돌파구로 평가되나?
6. 총 매개변수 6,710억인 모델의 실행 비용을 **파라미터 수로 추정하면 안 되는** 이유는?
7. AI 에이전트가 전통 소프트웨어와 갈라지는 **핵심 차별점**은?
8. 에이전트의 네 특징 중 **"인지 및 행동"**은 어떤 패턴으로 이어지나?
9. 온도를 0으로 두면 무슨 일이 일어나며, 어떤 상황에서 그렇게 하나?
10. **Top-K와 Top-P**의 차이를 한 문장으로.
11. 컨텍스트 내 학습에서 **모델의 가중치는 어떻게 되나?** 한계 네 가지 중 둘은?
12. **파국적 망각**이란 무엇이고 왜 위험한가? 완화책은?
13. 데이터가 **(입력, 두 응답, 선호 표시)** 형태라면 어떤 사후훈련 방법을 쓰나?
